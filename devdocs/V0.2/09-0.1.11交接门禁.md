# 0.1.11-dev → 0.2.0-dev 交接门禁

> 2026-09-29 用户裁决：普通 Map/Any 所有权、两个 Actor fallback、四类可达 legacy owner 必须在 **0.1.11-dev** 完成，之后才能转入 **0.2.0-dev**。此裁决替代“可先切 0.2 开发版本、把剩余迁移移交”的排期建议，不缩减 0.2 的 G1～G7 或现行不变量。

## 起点

- 源码基线：`4fbf6e40`，包版本 `0.1.11-dev`，开始时工作树干净。
- `0.1.10` 已有发布范围说明；其测试与未通过事项保持原始提交身份，不能充当本轮结果。
- 当前 goal 持续推进 0.1.11 收口，再实施 0.2 全计划。**2026-09-30 用户更新模型权限**：仅调用 `gpt-6.1-sol/xhigh` 与 `gpt-6-luna/max` 子代理，不再调用 Astra；此项替代 2026-09-29 的 Astra 授权。主代理统一接口、集成、构建与验收。已保存的 goal 初始描述不覆盖后续用户授权。

## 必须全部关闭的三组工作

| 工作 | 收口证据 | 不满足收口的情况 |
|---|---|---|
| 普通 Map/Any 所有权 | 普通生产 API 的类型标签/描述符、owner/borrow/escape、持久 clone、get/values、overwrite/remove/destroy 连通；必要的 checker/MIR/消费者合同与正反例齐全；真实 native 产物 L3 检测通过 | 仅受限 MapRoot、仅测试原型、仅拒绝解包、观测到 possible-loss 的测试 exit 0 |
| 两个 Actor fallback | `actor_nested_func_capture.mimi` 和 `actor_nested_func_shadow.mimi` 保留需求与输出，环境/状态/mailbox 语义由统一合同承载；default/direct 执行与证明边界一致；完整 census 无这两条 fallback | 换 fixture、去掉 capture、关闭诊断、将正例改成拒绝或仅修改统计标签 |
| 四类 legacy owner | CodegenLegacyRemainder、FlowVerifierCompatibility、FfiVerifierCompatibility、DualVerifierCompatibility 的生产依赖逐项迁移；原 body accessor 和旧语义消费者实际退役；所有调用边可审计且功能回归通过 | 改名/挪文件，包装旧 AST 消费者，删测试，隐藏回退或把必需能力隔离为不支持 |

每组可以拆分可验收切片，但切片通过不等于整组已关闭。原 owner 删除前置中的泛型、Flow、FFI、验证引擎等依赖均须列入实际实现工作，不以一个数字归零代替行为保持。

## 施工与证据

1. 保存固定基线、原例、测试/路由/内存结果与未验证状态。
2. 每个切片先明确 L1/L2/L3、修改文件与消费者接口；子代理避免同时编辑相同文件，主代理统一构建，防止混合产物。
3. 完成实现与有意义正反例后做专项验证，集成后按仓库要求跑完整门禁。保留错误结果，未运行与失败不得归入通过。
4. 三组全部有可复核关闭证据后，才允许更新 Cargo/CHANGELOG 为 `0.2.0-dev`；无需为了交接额外发布远程 tag。
5. 将可复用机制、反例与证据交给 0.2 的 B-01/B-05/B-08/B-09；0.2 候选语义仍须各自设计裁决和实施验收，不能因 0.1.11 完成就自动签收。

本文件记录交接要求，**当前三组均未签收**。实现进展分别记录于 [Map/Any 工作记录](../v0.41/map-any-contract-0.1.11.md)、[Actor 工作记录](../v0.41/actor-closure-0.1.11.md)、[legacy 工作记录](../v0.41/legacy-retirement-0.1.11.md)；这些链接的产物需实际创建后才能作为证据引用。
