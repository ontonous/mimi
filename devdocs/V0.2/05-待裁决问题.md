# 0.2 待裁决问题与实验闸

> 状态：**提议，全部待裁决**。本文件把需要推翻或扩展的旧规则摆在明处；“推荐”不是现行语言规则。现行权威是 [内核卡](../kernel-card.md)、[语言规范](../../docs/language-spec.md)、[架构修正案](../v0.31/architecture-amendment-1.0.md) 和已核实的实现。pre-1.0 允许 breaking，但每次 break 必须同 phase 重新挣回 L1/L2/L3 与双后端等价。

## D-01 普通值的复制操作

**现状/冲突**：当前资源模型以 move 与线性义务为核心；用户判断要求普通数据默认按值理解，但自动 COW 会引入可能的隐藏分配。

**推荐**：普通可复制类型在形成第二个可用值时具备逻辑独立性；实现可以 move 消除或 COW，强制成本约束看穿优化依赖。大值何时要求显式 `copy/clone`，由可用性与成本实验决定，不先承诺所有赋值无成本。

**备选**：A. 普通赋值总是逻辑复制；B. 仅小/显式 `Copy` 类型自动复制，其余显式复制；C. 所有大对象默认 move。比较 W2 撤销自然写法、W3 热路径、跨函数参数和诊断修复轮。**闸**：复制隔离无例外；被声明无分配的路径不存在可能的 COW 分配；文档对普通赋值与函数实参的行为一致。裁决后同步 `docs/language-spec.md` §2.4/§6.2 与内核卡。

## D-02 自动清理与严格义务边界

**现状/冲突**：内核卡 §3 明确 `MutexGuard` 必须 `mutex_unlock`，遗漏 E0256；文件和 Session 等目前与线性消费紧密绑定。用户判断建议把释放资源与完成协议分开。

**推荐**：锁守卫、普通文件/缓冲区属于“独占、可自动清理”；会话端点、导出/提交凭证属于“严格终态义务”。显式 close/flush 的可报告错误仍由调用者处理；自动清理只提供规定的本地释放，不证明持久化或远端确认。

**备选**：全部维持显式解锁；或一律自动 drop。前者要证明普通代码成本可接受，后者必须证明不会遗忘业务协议。**闸**：正常、早退、`?`、Flow rollback、协作取消、进程 abort（排除保证）逐项有规则和反例；部分初始化/部分 move 只清理残余；`defer` 与自动清理顺序、清理时再次失败、可重入析构和 panic/unwind 模式有明确结果。普通 Map/Any 的 clone、借出值、overwrite/remove 与嵌套 payload 不得从 MapRoot 特例推断；不受控析构回调在 registry 锁外运行，代际先失效且无死锁。`MutexGuard` 行为若改判，更新内核卡、错误码样例、stdlib 和迁移指南，并双后端重跑。

## D-03 属性推导与泛型组合

**现状/冲突**：当前 `Free T`、`linear T`、`linear drop T` 约束与容器/闭包的渐进放行已有边界；继续为 `Option`、列表、投影、闭包分别开洞会降低预测性。

**推荐**：语义上独立推导“能否逻辑复制、能否自动清理、是否有必须结算的义务、可否跨任务转移”。泛型体按声明约束检查，实例化时递归代入；`Option<T>`/记录/列表继承元素义务并保留残余所有权。表面语法可沿用线性 kind 或另设计，但不新增会擦除义务的默认泛型。

**Any 必须同轮定案**：静态有类型容器与动态异构容器使用一致的 payload 描述和所有权规则；擦除静态类型时保留可复制/可清理/严格义务/跨任务属性的约束。比较“带 kind 约束的存在类型包装”和“分开的 copy/owned/protocol 动态包装”等实现，选择能承载完整必需组合的方案；不能让无约束 Any 默认为 Free，也不能靠禁止全部严格载荷逃避组合目标。运行时类型标签只能验证具体类型，不能补救静态义务被擦掉的漏洞。

**操作表先于编码**：采用 [Map/Any 候选操作表](01-语义核心.md#12-mapany-取值与所有权)冻结借用读取、快照、移出、替换、克隆、销毁的所有权后置条件。缺键与类型错配须不同结果；`get_or_default` 的默认值只能在缺键时适用，不能证明已有载荷类型或吞掉错配。解包失败时容器与原 owner 保持有效；替换/删除旧严格义务必须显式归还或合法结算，不能隐式 drop。闭包、泛型与跨任务调用采用相同规则。

**闸**：记录、`Option`、`Result`、列表、普通 Map/Any、闭包、泛型和部分提取在同一负测规则下拒绝遗漏/二次消费；动态 Any 的 payload 类型与 owner 身份在运行时/静态边界一致，`get/values` 的借用或快照寿命可检查；新增容器无需重写每种语法路径的所有权特判。若实现做不到，记录阻塞、修订属性规则及 MIR/Drop plan 并复验；不能删去这些必需组合后发布 0.2。

## D-04 Flow 组合与嵌套

**现状/冲突**：[修正案条款 2](../v0.31/architecture-amendment-1.0.md#条款-2永久禁止-flow-嵌套-flow)将 Flow payload 持有另一 Flow 判为永久禁止；[Grouped Flow 愿景](../vision-grouped-flow-and-zigmi.md)通过独立 region + router 实现组合；用户判断希望重新审议一律禁止嵌套。

**推荐**：0.2 必须支持显式 owner 持有**多个独立 Flow 的不透明句柄/受控租约**，每个 Flow 自有身份、世代、失败归属，router 顺序显式；2/4/8 实例及真实后台任务均须验收。直接在 Flow payload 嵌入另一个 Flow 仅作单独实验；只有证明代际所有权、析构、转移、失败恢复和组合复杂度可控，才正式推翻修正案条款 2。不得把所有权组合误称为联合事务。

**闸**：W2 多个 Flow 在成功/失败/取消交错下无旧别名或义务遗失；2/4/8 region 对比实际分析成本与自然调用代码；必要时保留直接嵌套禁令，但独立组合 API 不得降为仅有两实例的演示。裁决记录须注明修正案的覆盖条款，不能只改本规划。

## D-05 模块名称与语法

**现状/冲突**：[规范 §6.14](../../docs/language-spec.md)明确文件级 merge、重复导出错误、普通 `M::f` 不支持。

**推荐**：保留文件为模块边界，新增包/模块身份、别名和限定访问；`use fs as files; files.read(...)` 仅作**示意拼写**。限定解析必须能与字段访问及 Flow `::` 共存。裸名引入若保留则要求显式选择；库新增公开项不能破坏原先限定调用。

**闸**：两个 `parse` 同时导入并调用正确实现；标准库、trait 方法、LSP、fmt、FFI 与增量接口摘要都使用同一 SymbolId；带 Mimi body 的 C export 另有外部 wrapper 身份与不可源码命名的内部 body 身份，递归不经 wrapper 错 ABI；包版本/锁文件、重导出、循环图、初始化顺序和缓存失效规则可复现。影响分析把 API/合同变化、实际重编、行为可达调用者与测试分开；接口摘要不变的私有实现变化仍可能改变运行结果。对支持的依赖图不能漏报，对动态/FFI/编译期生成未知边界必须扩大范围或明确标记未知。旧 merge 项有机械迁移建议。确定拼写后更新规范、EBNF 和迁移工具。

## D-06 效果集合与公开边界

**现状/冲突**：[规范 §2.7](../../docs/language-spec.md#27-capability-invariants)删除了无法强制的 `with` 效果子句；Resolved effect 字段存在并不意味着效果检查已可用。

**推荐**：先实现有限效果集合：文件读/写、网络、共享修改、阻塞、挂起和必要的 spawn 分类。私有函数推断，公开接口声明上界；调用、trait/泛型回调、闭包与 FFI 都必须传播。`alloc` 由成本门禁独立处理，但可在查询中同时展示。语法最后选择，旧 `with` 不因字段存在而复活。

**闸**：给纯公开函数引入隐藏网络调用必须报错；未知 FFI/dynamic call 不被推成纯；不在受信证明子集的调用给原始 `NotInTrustedSubset`，不是 `Proven`；Flow rollback 中不可逆外部效果的旧约束继续成立。

## D-07 能力的授予与范围

**现状/冲突**：`make_token()` 当前提供线性编号，`read_file_guarded` 的 VM 实现将读取转发给普通 API；这不证明目录范围隔离。

**推荐**：能力由宿主授予，并绑定目录/端点等可验证范围；静态检查要求携带权限，动态边界再检查实际对象。可重复的受控读取权限可借用，一次性操作凭证可线性消费。API 明确谁能委托、转移和撤销。

**闸**：列出所有**安全 Mimi 代码可达**的同功能入口（裸 builtin、stdlib、允许的 FFI、动态加载、任务消息）的授权矩阵；路径穿越、符号链接变化、非法端点、跨任务代理绕行不能越权。任意进程内不受信 native FFI 无法由类型系统约束，须禁止、列为受信宿主责任或置于隔离进程。宿主持有资源对象与动态检查的竞态风险需在目标平台上验证；范围无法安全验证的操作保持不发布。`SystemToken` 向新能力迁移时列出保留、废止与兼容边界。

## D-08 取消、终止和责任移交

**现状/冲突**：当前线性恰一次规则不等同于“远端任务已停止”，旧 Actor/FFI 异步路线又各有取消语义。

**推荐**：分离 `request_cancel`、`join/ack`、`transfer_cleanup` 与终态结算；本地静态规则检查每条路径的责任归属。超时是明确结果，不能制造虚假的已停止状态。进程 abort 不承诺析构；外部进程不响应不由类型系统保证终止。

**闸**：W2 后台任务在正常、失败、重复取消、不可响应、宿主故障、两个任务交错下的结果可观察，VM/native 一致；在终态处理确实完成时，完成与取消同时到达恰有一个本地回执，另一方不得重复结算；不响应/abort 可保持未决，不伪造终态；未处理 ticket 编译拒绝。终态权限与可自动清理资源的关系在 D-02 共同定案。

## D-09 旧 0.2 愿景的范围

**现状/冲突**：[旧愿景](../vision-grouped-flow-and-zigmi.md)把 Grouped Flow、zigmi 0.2、Zig 状态机提升和安全关键合规报告安排在 0.2 附近；用户的新判断把通用值、资源、模块、效果、成本与真实持续修改作为 0.2 定义。

**推荐**：0.2.0 的发布主线是四类原生应用和必需组合网格的语言闭环；多 Flow 的独立组合必须完成，Grouped Flow 作为命名路由器抽象是否采用由 D-04 裁决。任意 Zig 状态机自动提升及安全关键合规报告属于单独产品目标，不以其旧排期阻止或替代 Mimi 0.2 的语言验收。其资产可复用模块接口、MIR 与验证器事实查询。

**闸**：P0 提供当前真实完成度、工程预算、依赖和对四程序的直接收益；预算只决定投入与顺序，不决定砍掉 G1～G7。若要把 Zig 状态机提升另列为 0.2 必需项，先写独立需求、可信语义桥接和实际目标程序，不用旧排期文字当证据。

## D-10 成本约束范围

**现状/冲突**：用户希望性能代价可解释，但不同实现的自动复制/COW、析构、动态回调使简单“零成本”叙事不可信。

**推荐**：0.2 首个强制约束为所有可达路径 `no_alloc`；报告分“必然/可能/本次实测”，覆盖深复制、COW、扩容、析构和调用传播。设备搬运只预留分类，不在 0.2 承诺 GPU 调度或精确 CPU 时间上界。

**闸**：先写清函数区域的进入/退出、预分配资源、warm-up、运行时/VM 管理开销、跨线程分配与 FFI 的计数边界。W3 热路径静态无程序可见的可能分配，native 物理计数在登记范围内为零；插入一个可能分配的回调、析构或错误分支会在编译时拒绝并指出原因链；优化结果不改变已声明保证。

## D-11 长期普通状态与 Actor

**现状/冲突**：[规范 §1.1](../../docs/language-spec.md)要求跨调用持续的可变业务状态进入 Flow；§6.4 把 Actor 业务状态变化交给 Flow，并移除了用户可见的 Actor `mut` 业务字段。0.2 目标要让文档内容、光标、缓存等长期存在的普通数据无需逐项状态转移。

**推荐**：以**操作是否合法依赖离散阶段**为 Flow 强制条件；长期普通数据可封装在单一 owner 下，通过独占访问与不变量修改。Actor 隔离只解决并发访问，不能让未声明阶段变化绕过 Flow；Actor 可以保有不承载阶段合法性的普通数据，但必须有明确的跨消息所有权与效果规则。

**备选**：保留现行“持续可变业务状态一律 Flow”的范围，改进局部字段更新与 Flow ergonomics。**闸**：W2 光标/缓存、文档内容、关闭后编辑、Actor 邮箱更新四类程序用同一判定准则分类；已声明的 `Closed` Flow/协议不能绕开类型门禁。Actor `runs Flow` 的持久状态与合成转移在 native/VM 同义，self-call、显式同名方法和闭包环境身份均可验证；当前 E0722 只算诚实拒绝。普通布尔字段是否暗藏业务阶段只能由 API 设计、lint 与审阅发现，不能宣传为编译器可自动证明。若改判，必须显式修订规范 §1.1/§6.4 和相关 Actor 诊断，不能只改示例。

## D-12 可执行与可证明的边界

**现状/冲突**：当前规范有可执行、运行时契约和受限 Verified Core；0.2 又引入效果、模块摘要与复杂资源义务。若把 SMT 暂不支持写成普通程序不可用，通用性受限；若把运行通过写成静态证明，则形成虚假保证。

**推荐**：结果分三层：① 类型/资源/效果检查通过，可以执行；② **被运行时 evaluator 支持**的前后置条件按指定模式检查并产生可观察失败，未支持项不得声称已检查；③ 静态证明在版本化受信子集内给出 `Proven` 或 `Disproven` 等原始结论。强制证明模式沿用现行 [Verified Core §5.7](../../docs/language-spec.md#57-result-states-stable) 的八种状态：`Proven`、`Disproven`、`NotInTrustedSubset`、`SolverUnknown`、`Timeout`、`InfrastructureError`、`RuntimeOnlyContract`、`NoObligations`。仅有实际已证的义务才标 `Proven`；`NoObligations` 允许表示无待证义务，但不能用来宣传某项性质已证明。普通编译不得静默略过宣称强制的合约。证明缓存绑定源码、模块接口、MIR/TypeDesc、目标数值语义、证明逻辑版本、受信假设/外部摘要、求解器配置与版本。

**闸**：同一真实程序分别展示可执行但不在受信子集、运行时契约失败、静态反例及静态已证四种情况；另测 `SolverUnknown`、`Timeout`、`InfrastructureError`、`RuntimeOnlyContract`、`NoObligations` 的原样透传。无合约、未到达验证器、未证的 `math`/ghost 事实、未审计 FFI 假设和旧缓存都不产生伪 `Proven`。现存简单 `bool` 字面量合同的 Proven/Inconclusive 分歧须以原样例修成一致且正确的结论，不能换成 `i32` 或把该必需形状移出受信子集就声称解决；更复杂公式的不受信边界另行裁决并准确拒绝。FFI 在顶层/Actor/Impl/Flow/初始化/默认参数中的义务不因 route 改变而漏扫。普通编译与强制证明的 CLI/产物状态明确区分，并按现行 [Verified Core](../../docs/language-spec.md) 逐条迁移。

## D-13 修改位置、别名与求值顺序

**现状/冲突**：[规范 §6.2](../../docs/language-spec.md#62-permissions-viewmutateconsume-vs-mut-stable) 与 `src/core/infer/call/simple.rs::mutate_place_of` 只准变量或单层字段作为 mutate 实参；嵌套字段与索引位置报 E0434。旧规范将嵌套写回推迟到 1.x，与 0.2 的 W2 深层节点编辑、W3 元素热点冲突，须正式改判。

**推荐**：位置以 root 身份加字段/索引投影表达，作用域、独占权、写回和残余义务都引用该身份。允许普通嵌套字段和单个动态元素修改；实参及索引按规定次序求值一次，不能在写回时重新求值。静态不相交字段可同时借用；父子位置、同元素重叠拒绝；动态双索引无法证明不重叠时，使用有类型的运行时拆分结果建立互斥凭证，未取得凭证不得放行两份独占访问。具体 API 拼写待定，不以用户手动复制整棵记录替代该能力。

**同轮决定**：共享存储的唯一化在借用可观察之前完成；活跃借用期间不能令原地址失效的扩容/替换被放行。普通可失败函数中已发生的写入是否保留要明文规定，推荐按顺序保留已经执行的写入；只有声明 rollback 的 Flow 才适用其回滚合同，不引入全语言隐式事务。部分 move 的位置不可再借用；错误与取消退出仍按同一残余清理规则。

**闸**：深层字段、动态索引、互斥字段、父子重叠、相同/不同索引、带副作用索引、越界、COW 快照、扩容与活跃借用、部分 move 后修改、错误退出均有独立 oracle。单个动态索引和合法不相交字段必须真实通过；冲突及无证明的双独占访问准确拒绝。V-12 在 checker/MIR/三执行消费者/验证边界及 no_alloc 组合中验收，更新 §6.2 的旧延后条款和 E0434/E0435 的迁移样例。

## D-14 并发可见性、挂起与线程归属

**现状/冲突**：现行 task-local 借用规则、native 原子操作和 Actor mailbox 分散在 checker/runtime；0.2 的 F-04/F-08 定义取消责任，但没有替代共享内存与任务调度合同。当前部分原子实现使用 SeqCst，只是实现事实，仍需明确语言承诺。

**推荐**：可跨任务移动、可跨任务共享、必须在原线程清理分别推导。默认禁止 view/mutate、持有的 MutexGuard、线程绑定资源跨任务或跨挂起点逃逸；安全转交须有显式 owner/执行线程保证，不能仅因值 owned 就放行。定义同任务程序序、发送到对应接收、unlock 到后续成功 lock、任务完成到 join 确认的可见性边。首版普通原子 API 推荐顺序一致；引入更弱顺序须另有正式合同与 litmus。

**Actor 和活性**：冻结每发送者消息顺序、跨发送者允许交错、单个 turn 的重入点，以及同步 self-call 与发回自己 mailbox 后等待的区别。推荐默认 turn 不隐式重入；静态可识别的自等待拒绝，动态依赖循环给明确诊断/边界。不承诺任意锁图无死锁、公平调度或远端一定终止。取消未确认时保留责任，不凭 timeout 制造同步完成或资源释放证据。

**闸**：消息传值、锁保护发布、join 后可见、原子顺序、guard 跨挂起、线程绑定析构、闭包捕获和 self-wait 各有正反例；固定调度与允许偏序共同界定 L1。F-10 交付规则/MIR 事件及 oracle，F-06/F-09 实现，A-11 对生成 native/runtime/FFI 做实际并发与内存检测；无检测覆盖不得写为无数据竞争。更新规范 §6.2/§6.4、相关原子 API、任务和清理说明。

## 裁决记录模板

每项由实现负责者在对应任务开始前填写并保留历史：

```text
ID / 日期 / 决策状态 / 负责角色：
旧权威与准确条款：
选择的规则和未选择方案：
最小正例、反例、故障路径：
安全依据与可观察语义：
设计接受依据 / 尚需实现验证的假设：
成本/复杂度证据：
迁移影响（旧代码 → 新代码）：
必须同步的内核卡、规范、EBNF、stdlib、诊断：
checker/MIR/四消费者/verifier/route/旧边删除证据：
实现已验证的任务与 evidence ID / 规范已生效的提交：
未支持的非目标范围、必需目标阻塞和回滚条件：
```

设计接受后允许按规则推进明确隔离的实验；实际 break 必须在同一 phase 重新挣绿后才合入默认支持面。没有实现证据不能记实现已验证，没有规范/内核同步不能记规范已生效；实际发布仍须通过 [发布门禁](04-迁移与发布.md#发布门禁)。本轮新增 D-13/D-14 与深化 D-03 均仍待裁决。
