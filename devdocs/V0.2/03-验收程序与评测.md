# 0.2 验收程序、持续修改与评测合同

> 状态：**预注册验收设计**，不是现有测试已通过的报告。P0 的 B-02/B-04 需把本文件所述需求转为带路径、输入、期望输出、提交和 hash 的固定语料；后续不能删掉难例来提高通过率。验收口径继承 [MIR 执行计划 §6](../MIR_EXECUTION_PLAN_2026-09-06.md) 的 L1/L2/L3、默认路由和证据要求。

## 1. 程序组合与真实用户任务

四程序分别考验日常通用性、跨时间资源协议、性能约束，以及长期运行的网络/FFI 组合。可以复用已有 `projects/`、`tests/real_world/` 的代码或参考行为，但必须保留这里固定的需求。**语言支持困难时应登记缺口并继续开发，不能把产品需求改成示例能过的形状。**四程序只是端到端底线；复合类型、stdlib、调用方式与边界的独立组合网格仍须通过，不能以四个示例替代完整目标面。

| 编号 | 目标程序（建议路径，尚未创建） | 核心验收问题 |
|---|---|---|
| W1 | `projects/mimi02-config-tool/`：文件/JSON 命令行工具 | 普通值、错误处理、两个同名库、限定导入、范围能力、安装 |
| W2 | `projects/mimi02-document-core/`：无 GUI 的文档或图像核心 | 快照与节点身份、撤销、后台导出、取消、Flow 终态和资源义务 |
| W3 | `projects/mimi02-audio-kernel/`：数组/音频处理内核 | 独占原地更新、确定数值、所有可达路径无分配、性能报告 |
| W4 | `projects/mimi02-loopback-service/`：本地网络服务与受信 C 库集成 | 网络效果/端点能力、并发、取消、FFI ABI 与生命周期、模块替换、长时间运行 |

### W1：文件与 JSON 工具

**固定故事**：读取一个 JSON 配置与一组文件，校验并合并字段，输出确定性 JSON 报告；无效输入返回明确错误，`--dry-run` 不写文件。项目必须分别导入两个都公开 `parse` 的模块，并能在调用点看出来源。不同输入目录由宿主授予不同读取权限；未经许可的路径在动态边界拒绝。

**首次验收**：正常输入、空文件、畸形 JSON、重复字段、Unicode/NUL、权限外路径、写入失败、两模块同名导出均有固定 oracle；同一输入的 VM/native 输出及退出类别一致。安装/锁文件/离线构建证据单列，不能只从源码目录运行成功。

**首批固定 oracle（B-02 写入数据文件）**：含重复 JSON key 的输入报 `DuplicateKey` 类错误且不产生输出文件；`--dry-run` 对合法配置给出与正常模式相同的计算报告但文件系统写入计数为零；越权目录读取在打开目标前失败；两个 `parse` 的结果分别带可辨识来源。实际输出格式、排序、退出码在创建 fixture 时冻结，不能到测试实现完成后再决定。

**连续修改**：C1 把 JSON 解析库替换为接口兼容实现；C2 为输出增加来源字段；C3 收紧目录读取范围；C4 增加只读预览模式。每次都分别记录 API/合同变化、实际重编范围、行为可能波及的调用者与测试、效果变化、测试回归和修复轮数；C1 即使接口摘要不变，也不能据此排除行为回归。

### W2：文档/图像核心

**固定故事**：文档拥有节点存储、可复制的修订快照、节点 ID、撤销历史和一个后台导出任务。用户可以编辑普通数据、保存快照、撤销；关闭文档后不得再编辑。导出使用快照；终态被确认时按“完成 / 失败 / 已确认取消”之一结算，外部不响应时保持可观察的未决责任。取消请求与实际停止分离；正在使用的快照和输出资源在责任移交前不可释放。无需完整 GUI，提供 CLI 驱动的确定性事件脚本。

**首次验收**：

1. 复制快照后更新节点，只改变新修订；合法 `NodeId` 指向明确的存储身份，删除/失效 ID 给出确定错误。
2. 关闭后的提交静态拒绝或由类型化动态边界拒绝；光标移动、布局缓存更新无需 Flow 转移。
3. 导出成功明确完成并释放临时资源；写入失败保留可报告错误并结算本地责任；取消请求后等待确认或移交清理责任，不把 `drop(task)` 假装为成功取消。
4. 至少协调两个独立 Flow/协议对象而不产生隐式乘积状态。外部文件写入不被 Flow rollback 假装撤回；需要可靠发布时使用明确的临时文件与提交步骤，失败保证按文件系统实际能力标注。

**连续修改**：D1 将撤销存储从完整快照改为差量/分块结构，保持用户可观察修订；D2 将已有取消扩展到**写入中途**，不发布半成品并保持可重试的责任归属；D3 给失败类型增加一个错误变体；D4 将导出实现移到单独模块并收紧其效果；D5 允许两个后台任务并发但保持资源结算。每项都要展示接口/效果/成本与受影响调用点；评测时从各自冻结的起始版本独立施加修改，不靠前一题的答案。

**首批固定事件脚本（B-02 写入数据文件）**：`创建 → 编辑 A → 保存快照 S1 → 编辑 B → 撤销 → 用 S1 导出 → 请求取消 → 等待/移交`。应观察到 S1 不受 B 影响、撤销后内容等于 A；若终态处理完成，恰有一个本地回执；若只完成责任移交或外部不响应，记录新责任人或未决状态，不能伪造终态。未完成的临时输出不会被报告为已发布。另有受控调度脚本让“完成”和“取消”相邻到达，允许结果依调度为完成或已确认取消，但一次已完成的运行只能有一个终态回执。故障脚本覆盖打开后写入失败、取消确认失败和清理失败，原始错误与清理责任必须可追溯。

### W3：数组/音频热点

**固定故事**：对预分配的样本缓冲区做可复现的原地处理，并写出校验摘要。输入包含空块、极值、不同长度、重复运行；数值规则必须遵循 Mimi 的机器整数/浮点裁决与 trap 分类。处理热路径显式要求无堆分配，创建/销毁输入缓冲区在热路径外。

**首次验收**：checker 对动态调用、隐式写时复制、扩容、析构或错误路径上潜在分配给出拒绝或可证明无分配；实际计数验证零分配；VM/native 数值与 trap 分类对拍。报告环境、输入、p50/p95、峰值内存、分配/释放、复制与二进制大小，区分静态保证和本次测量。

**连续修改**：H1 在不变输出下更换处理算法；H2 增加可选滤波但保持无分配合同；H3 把数据结构换为可共享快照的普通列表，先观察热点的可能 COW 被成本门禁拒绝，再用独占缓冲区或经证明的优化完成同一需求且保持无分配。设备/GPU 接口只作设计探针，0.2 不要求实际加速。

**首批数值 oracle（B-02 写入数据文件）**：热路径以预分配 `i32` 样本缓冲区为输入，用 `i64` 中间值计算两倍增益，再截到 `[-1000,1000]` 并原位写回；`[-2147483648,-501,0,501,2147483647]` 的结果为 `[-1000,-1000,0,1000,1000]`。空缓冲区保持空，输入缓冲区容量不变。H2 的滤波定义与预期向量在实现前另行冻结，不能只比较两个 backend 恰好同错的输出。

### W4：本地网络服务与 FFI 集成

**固定故事**：在受宿主端点能力限制的 loopback 地址启动 JSON 请求服务，两个客户端并发提交请求。服务将请求交给独立模块解析，通过一个受信 C 库完成确定性校验，再写入响应；服务接受协作停止请求，必须等待或移交每个在途请求的资源责任。调用 C 库的 ABI、内存所有权和效果摘要明确记录；另向 host C 测试驱动导出一个带 Mimi 实现体的状态查询函数，以验证 C wrapper、内部递归/互调和同名符号边界。不受信 native 代码不能偷偷进入同一受限进程。项目按离线锁文件安装，可从非源码目录启动。

**首次验收**：正常请求、畸形 JSON、并发顺序、断连、服务停止时仍有在途请求、越权绑定或外联、FFI 返回错误和错误所有权声明均有冻结 oracle。导入 C 函数与导出 Mimi 实现体分别验收；host C 调用导出 wrapper、Mimi 内部调用同一 body、递归及共享库符号表的结果与 ABI 一致，带导出体的库目标不因缺 `main` 被误判为语言失败。静态效果/能力边界拒绝未授权入口，动态端点检查阻断实际越权；VM/native 的允许事件偏序、错误类别、已确认终态和资源释放一致。长时间运行与重复启停须有内存、句柄和线程证据；只测一条 happy path 不算完成。

**连续修改**：S1 将校验库替换为同 ABI 的另一实现并核对行为影响；S2 增加请求超时与在途责任移交；S3 收紧允许监听和外联的端点范围；S4 将传输层拆到新包并保留公开接口与锁文件可复现性。每项从独立冻结的起始版本开始；至少一次修改交给未参与对应功能实现的维护者，沿用同一需求、诊断和隐藏验收，检验方案是否只适合原作者。

**首批固定 oracle（B-02 写入数据文件）**：相同有效请求在两客户端交错顺序下得到同一内容校验；坏 JSON 只失败该请求，不终止服务；停止请求到达时已受理请求须完成或显式移交，未受理请求不得假装已处理；未授予的端点在绑定/连接前拒绝。C 库参考向量与错误码在独立 fixture 中冻结，不由 Mimi 输出反推；网络端口、调度种子、超时与 FFI 构建身份进入复跑清单。

### 1.1 冻结语料的最低结构

每个 W/C/D/H/S 用例须有 `需求文本 → 独立 oracle → 输入与故障注入 → 允许的事件偏序 → 预期静态诊断或动态输出 → 适用平台/模式`。至少一份 host 语言参考实现或手算 oracle 与 Mimi 实现分离；测试生成器不得读取被测程序的输出反算期望。需求变更保留旧 fixture、理由与分母变化；**0.2 必需需求没有“移出后照常发布”状态**。未能在旧版 Mimi 自然表达的任务标为 `N/A（旧版不可表达）`，不记为通过或失败，也不从 0.2 分母中删除。

### 1.2 连续演进链

原 16 项 C/D/H/S 仍从独立起点运行，保留可比实验。另设两条必需累计链，由 A-10 建可自动验收的检查点，再由 A-04 做真实模型和独立人类交接；它们不计入原 16 项，也不能用某一链内通过的步骤替代失败的独立题。

| 链 ID | 固定顺序 | 每步继承与验收 |
|---|---|---|
| SEQ-W2 | W2 基线 → D1 差量撤销 → D2 写入中取消 → D3 错误变体 → D4 模块/效果边界 → D5 双任务 | 继承上一版源码、外部文档数据与历史回归；快照/撤销内容正确，既有错误与取消路径不退化，义务/接口/成本查询与实际结果一致 |
| SEQ-W4 | W4 基线 → S1 C 库替换 → S2 超时/移交 → S3 端点收紧 → S4 传输层拆包 | 继承上一版源码、锁文件与外部请求 fixture；停止与在途责任正确，旧能力不能从缓存恢复，替换后 ABI/行为与离线构建仍可复现 |

每个检查点记录父检查点 hash、实际 patch、需求与 oracle 版本、全部历史回归、路由、资源/效果/成本摘要及迁移日志。不得重置到参考解；需要人工干预或回退时保留失败点、时间与干预，记为该次自主整链未完成，修复后另起有身份的新尝试。构建缓存保留用于检验失效，同时以冷构建交叉核对；不能只靠每次清空缓存掩盖错误。进程升级前按协议结算活资源，不要求跨版本热迁移 native 句柄；外部数据/配置的兼容性进入冻结 oracle。

**判定**：发布验收要求两条参考工程链的全部检查点、累计回归和 L1/L2/L3 通过；模型整链完成率与人类交接达到 B-04 的预注册门槛。每条链至少一名未实现对应功能的维护者完整接手，允许与既定四名维护者重叠。模型另做 2 链×至少 2 模型系列×至少 3 种子，即至少 12 次整链尝试，预算在 B-04 单列；链内步骤相关，不按 9 个独立任务做显著性推断。整链统计作持续维护证据，不混入独立题的 2×2 因果比较。

## 2. 测试矩阵：从正例到攻击性反例

| 层 | 必需矩阵 | 通过定义 |
|---|---|---|
| 源码/checker | 值隔离、move/borrow、线性结算、作用域清理、模块冲突、效果越界、能力越界、无分配约束 | 合法自然写法准入；非法写法在执行前以稳定错误类别与主跨度拒绝 |
| MIR/L2 | 伪造类型/字段/模块身份、重复 drop、未结算义务、错误 effect/cost receipt、错路由 | 任何 reference/VM/native/LLVM/Z3/host side effect 前拒绝 |
| L1 | 同一源码与同一准入 MIR 的值、stdout/stderr、退出、trap、Result/Fault/取消终态 | 三执行消费者按登记观察模型一致；进程退出码 8 位截断时使用完整返回值或明确的比较规则 |
| 验证器 | 有效前后置条件、刻意错误条件、含未知效果/循环/外部调用的边界 | 保留现行 Verified Core §5.7 原始状态：`Proven/Disproven/NotInTrustedSubset/SolverUnknown/Timeout/InfrastructureError/RuntimeOnlyContract/NoObligations`；除真实 `Proven` 外均不写成已证，不要求整门语言 SMT 可证 |
| L3 | 快照 COW、容器嵌套、闭包捕获、FFI、导出取消、文件/锁清理 | 已发布 native 路径有 ASan/Valgrind 或等效内存证据；错误释放、泄漏、use-after-free 为零 |
| 普通 Map/Any | 生产 `set/get/values/remove/clone/destroy`、动态 Any 类型错配、借用/快照逃逸、覆盖与清理重入 | MapRoot 的干净内存日志只计 MapRoot；普通生产调用在失败/并发/重复启停下单独达到 L1/L2/L3，析构回调不持有 registry 锁 |
| 修改位置 | 嵌套字段、动态索引、不相交字段、父子/同元素重叠、COW/扩容、部分 move 与有副作用索引 | 合法嵌套与单动态元素修改真实写回；求值一次，冲突拒绝；动态拆分凭证不可伪造，错误路径与快照结果有独立 oracle |
| 并发合同 | 转移/共享/线程亲和、send/receive、unlock/lock、join、原子顺序、挂起和 turn 重入 | 遵循冻结可见性边和允许偏序；禁止借用/guard/线程绑定资源非法逃逸；race/悬空/重复终态由生成 native 路径实际检测 |
| Actor/Flow | VM 与 native 的 `runs Flow` 合成转移、自调用、显式同名方法、nested capture/shadow、取消/故障 | 必需形状都按同一状态与 mailbox/环境身份通过，不能只把 native 误报改为 E0722；两个现存 legacy fallback 有明确归零证据 |
| 导出 ABI 与证明 | C import、带 body 的 C export、内部递归与外部 wrapper、各类 callable/初始化表达式里的 FFI 合同及 `bool` 合同 | 同一 ABI/义务事实贯通默认、显式 MIR、direct API、验证器与 host C oracle；错误合约不能被漏扫或由 E0439 分歧冒充已证 |
| 路由与旧权威 | 默认 `run/build/verify`、显式 MIR 和直接 API；带 import/回调/FFI 的完整调用图 | W1～W4、组合网格和公开 stdlib 的必需 Mimi 路径走 Canonical；外部 C 代码经受信摘要/ABI/故障边界验收；施工中未支持形状精确拒绝/明确隔离，RC 不以此豁免必需能力；无 Canonical-start 后回退 |
| 性能/成本 | 固定机器与输入的基线、噪声、可达路径成本、运行分配计数 | W3 热路径在 D-10 登记的程序区域静态无分配，native 物理计数为零；VM 管理开销另列；其他目标达到 P0 预注册预算或给出阻塞裁决 |

正常返回、`Err`、`?`、Flow rollback、Fault、协作取消、超时、进程 abort 的保证范围须分别记录。并发样例使用固定调度脚本或预先定义的允许事件偏序比较，不把不同线程的偶然打印顺序当成语义分歧。进程 abort/断电不属于自动清理承诺；远端不响应不属于静态取消成功承诺。动态权限只按已声明的运行时边界证明。

检测覆盖必须列清编译器测试进程、生成的 native object/binary、standalone runtime、FFI 库四个对象。ASan/TSan 等需要插桩时记录每个对象的构建与链接配置；使用 Valgrind 等动态检测时记录实际被运行的最终产物。ASan 与 TSan 使用独立构建，检测到一个组件不等于检测整条调用链。独立故障控制样本应确实触发检测器，release 产物不得包含故障符号；不适用、未插桩或未知覆盖的组件必须给替代检测与限制。尚无适用证据的必需路径保持未验证，不能豁免发布门禁。

### 2.1 组合覆盖最小网格

| 维度 | 至少覆盖的形状 |
|---|---|
| 载荷 | 标量、字符串、普通记录、独占资源、严格义务、嵌套容器 |
| 包装 | 直接值、`Option`、`Result`、列表、记录字段、泛型实例、闭包捕获 |
| 控制流 | 顺序、条件两臂、循环、早退、错误传播、任务取消、Flow 转移 |
| 边界 | 同模块、跨模块、stdlib、FFI、VM/native、验证器 |

不要求把全笛卡尔积机械展开，但**每个列出的包装、控制流和跨边界类别都属于必需覆盖**：至少与普通值、独占资源和严格义务分别组合，并有定向正反例、生成式变化和实际 native 运行。错误传播、取消、泛型和闭包不能被标为实验来获得发布豁免。新增容器/调用语法不能靠单一字面量位置的例外规则绕开该矩阵。

## 4. AI 实验：真实持续修改，而非基建自测

[既有 Phase F 报告](../v0.39/phase-f-report.md)明确使用参考解与手工失败轨迹，**没有真实模型输出**。0.2 的 A-04 必须另外运行真实模型；评测方法在看到结果前冻结。

### 4.1 实验设计

- 从 C/D/H/S 中纳入**全部 16 个**可独立验收的持续修改任务，覆盖数据结构、取消、错误类型、依赖替换、权限收紧、无分配、网络与 FFI；各题从冻结的起始版本独立开始，保留原始实现与隐藏验收，不在看见模型结果后删题。
- 固定模型名称与版本、采样参数、提示、工具权限、可用文档、最大轮次/时间/token 预算、仓库提交和运行环境。至少两个模型系列、每任务至少三个随机种子；保留全部尝试而非最佳样例。
- 先以不计入正式结果的少量任务试跑 harness、预算和隐藏测试隔离，再冻结正式方案。两版语言的任务给等价需求、相近初始上下文与同一可用时间/工具预算；查询工具若在旧版只能回答更窄的问题，报告这个不对称并撤销相应因果比较。
- 对**两版语言都可表达**的任务做 2×2 对照：当前规则/0.2 候选规则 × 基础诊断/语义查询工具。语义查询必须能在两版上给出同口径事实，四格才可用于区分语言和工具收益；若做不到，只报告能成立的配对比较，不声称独立的工具因果效果。16 项原任务全部进入 0.2 绝对验收；其中至少 **8 项**进入可比对照，P0 的统计功效分析可提高这一数量。若旧版无法表达足够多的原任务，须在看到结果前另外冻结同等级的可比任务，不能删去原 16 项。若四格对原 16 项均可执行，16 任务×2 模型×3 种子×4 条件 = **384 次尝试**；增补可比任务的尝试另计。某任务在旧语言不能自然表达则退出配对分母，作为 0.2 专属能力单独报告，不能当旧版失败拉高差值。
- 随机化任务顺序、隔离工作目录；模型不能读取隐藏测试及参考修复。工具输出含信任级别；提示注入/错误编译器事实不算已验证答案。

### 4.2 结果与结论边界

**主指标**：最终候选在冻结的隐藏功能测试及 L1/L2/L3 中全部通过的任务率。**次指标**：首次 check、修复轮数、回归数、改动行数、人工复核时间、编译器误导诊断、资源/效果/成本违例与工具调用开销。给出逐任务原始结果、配对差值和置信区间；比较以**任务为聚类单位**，模型和随机种子是同一任务内的重复观测，不能把 384 次尝试伪装成 384 个独立需求。

**人类维护者验收**：至少四名未实现相应功能的维护者在冻结任务上完成跨模块、资源、取消和热点修改；每人至少覆盖四项、四类程序均有人接手，平衡任务顺序并记录成功率、用时、诊断修复轮、回归和主观困惑点。具体任务分配与通过阈值在 B-02/B-04 预注册。W4 的独立交接是最低现场验收，不能由原作者自评代替。

若“新规则 + 工具”相对“当前规则 + 基础诊断”的配对成功率没有可信改善，或人类交接达不到预注册目标，则 G6 **未通过**：分析规则、查询工具、诊断和任务选取，修订并重新评测，保持开发版本。宣称 AI 优势至少要求预注册的主指标差值为正、区间不跨零，且不存在 L1/L2/L3 回归；不能用宣传措辞代替 G6 的验收。手工候选只能用于验证 harness，绝不可计入模型结论。

## 5. 每轮证据记录格式

每个任务/测试保存如下字段：`task_id`、需求版本与 hash、源提交/工作树摘要、编译器及最终产物 hash、目标平台、工具链/feature、输入/种子、预期行为、实际 checker/MIR route、四消费者结论、verifier 状态、运行/成本观测、失败分类、诊断、可复跑命令、原始日志 hash、证据位置、结论限制。连续链另有父检查点与累计回归清单；AI 尝试另有模型/提示版本、预算、工具日志和每轮 patch。字段合同与记录身份见 [执行与证据](08-执行与证据合同.md#4-证据记录与失效规则)。
