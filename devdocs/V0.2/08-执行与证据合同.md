# 0.2 执行与证据合同

> 2026-09-29 计划深化。本文规定如何执行与记录 0.2 规划，不提升任何候选语义为现行规范。G1～G7、W1～W4、原 16 项修改与完整公开 stdlib 范围保留；新增两条累计链和明确的基础操作/检测要求。任务状态见 [plan.toml](plan.toml)。

## 1. 权威与状态

| 对象 | 唯一维护处 | 其他文档的职责 |
|---|---|---|
| 产品目标与不可缩减范围 | [README](README.md) | 各任务映射回 G1～G7，不自行删目标 |
| 候选规则和待决选项 | [01](01-语义核心.md)、[05](05-待裁决问题.md) | 设计接受后方可指导相应实验，现行规范继续有效直到正式替换 |

| 任务/决策状态、证据引用 | [plan.toml](plan.toml) | 报告从此清单读取，不维护第二份手写百分比 |

任务采用 `未开始 / 设计中 / 实现中 / 验证中 / 已验收 / 阻塞 / 研究中`。只有带具体前置和证据的任务才能提升为已验收；研究中只用于实验任务。失败保留事实，阻塞记录具体原因、解除条件与负责角色，不用“已完成文档”冒充语言能力。

决策采用 `待裁决 / 设计已接受 / 实现已验证 / 规范已生效 / 重新审议`。设计接受记录规则、反例、安全依据和迁移，足以指导施工；实现验证要求相关任务与不变量通过；规范生效还需现行规范、内核卡、诊断和迁移同步。P0 的退出要求设计接受，RC 要求规范生效；实际 breaking 的默认支持面仍必须同 phase 重新挣绿后合入。

**验收依赖不是调查禁令。** 可以提前写 oracle、做隔离探针或设计下游接口；前置未完成时不能签收下游。阶段只是分组，任务依赖只能写明确的任务 ID 和决策 ID。F-01 不等待整个 P1；M-09/F-09 在 E-03 完成后联合验收，不能为了让阶段表好看而省略效果合同。

基础机制与生产集成也分开签收：V-06 提供值隔离机制/存储接口，V-11 承担普通 Map/Any 完整集成，避免口头要求相互先完成。M-06 验收全部公开模块身份与迁移清单，A-05 验收其中全部必需 body 的 Canonical 图；两者分工不缩减公开 stdlib 分母。

## 2. P0 必须留下的实物

下表是 B-01～B-09 的交付规范，路径是建议布局，**尚未创建的产物不能记已存在或已通过**。工具和数据可先在本地准备；需进入正式验收时，由 B-09 导出到仓库确定的跟踪路径或不可变工件位置。

| 产物 | 至少包含 | 通过条件 |
|---|---|---|
| baseline/manifest | 源 commit/差异 hash、编译器 hash、工具链、feature、目标平台、工作树与环境 | 同一版本的真实检查/运行；历史日志保持原来源；磁盘/依赖不足记环境未验证 |

| sequences/SEQ-W2、SEQ-W4 | 起点、顺序、检查点父 hash、累计回归、数据/缓存要求 | 全链 oracle 可执行；不会在每步重置源码、外部数据或参考解 |
| decisions/D-01～D-14 | 正式设计记录、旧条款、正反例、适用边界、迁移、实施任务 | 设计已接受；未决研究独立，必需规则不留空 |

## 3. 施工队列与应用增量

### 第一轮的三个可审核结果

1. **基线与验收种子**：B-01/B-02/B-09 形成真实文件、输入、oracle、失败分类和清单。针对当前 Map/Any 拒绝边界留存原例；不得把准确拒绝计作完整取值支持。
2. **基础语义联审**：D-01/D-02/D-03/D-13 共同确定复制、清理、严格义务、Any 与修改位置；D-04/D-08/D-11/D-14 确定 Flow/Actor/取消/并发。模块/效果/授权/成本/证明的设计同步准备，不能等 runtime 已定型才补摘要。
3. **能力家族工作包**：B-05/B-08 选一条有实际应用调用点的家族，列 checker/TypeDesc/MIR/各消费者/route/L3/旧边的工作量与依赖，使用固定 oracle 逐项交付。计划不以提交数或切片数推算百分比。

### 每阶段都交付应用增量

| 阶段 | 当轮实际产物 | 尚未完成时的诚实状态 |
|---|---|---|
| P0 | W1 JSON/文件 oracle、W2 事件脚本、W3 数值向量、W4 host C 与请求 oracle；全部修改和链起点 | fixture 可运行而 Mimi 未支持，记录各自结果 |
| P1 | W2 快照/深层节点修改、W3 元素修改、W1 普通 Map/Any 数据链及资源错误路径 | 未接通模块/网络/取消的部分不提前标完整应用 |
| P2 | W1 双 parse、W4 多包身份/锁文件；四应用的公开 stdlib 调用迁移 | M-09 待 E-03 联验；库目标与 executable 分开 |
| P3 | W2 导出/取消/重试、W4 在途责任和任务可见性 | F-09 待 E-03 联验，VM 成功/native 拒绝仍是阻塞 |
| P4 | W1/W4 范围能力、W3 no_alloc、四应用的真实效果/成本摘要与证明边界 | 未知 sink/成本明确拒绝，必需正例未过不签收 |
| P5 | 在真实应用增量上查询引用、Flow、义务、效果、成本和影响；试跑评测 harness | 试跑不计正式 G6；工具事实缺失保留未知 |
| P6 | 同一候选版本的四应用、16 独立题、两条累计链、真实模型/维护者与发布全量复采 | 任一必需门失败继续开发，不重新挑选需求 |

表中增量不替代 A-01～A-11 的正式前置；A 类任务可以提前进入实现中，但全部依赖与应用合同齐全才验收。对先行实验 profile，默认用户路径保持现行规则并可查询边界。

### 每个能力家族的交付卡

卡片必须写清：关联 G/任务/D/应用 fixture；允许与拒绝的自然写法；类型/位置/义务/effect/cost 身份；MIR validator 攻击性反例；reference/VM/native 观察与 verifier 原始状态；默认/显式/direct route；native 检测覆盖；准备退出的旧生产边；实际编译和验证资源。未到达的项目保留未验证，不用模板勾选替代证据。

WIP 上限仍为一个等待全链验收的新语义家族；独立 oracle、模块设计、证据工具和已闭合家族的旧边删除可并行。若全链等待持续增长，优先解决共同根因与验证基础，不继续累积新的默认准入。共用 TypeDesc、位置、effect 摘要有明确 schema 版本与迁移，避免多个局部 helper 重新猜语义。

## 4. 证据记录与失效规则

实际证据由 B-09 后续收集器生成；当前结构检查器只检查规划结构，不读取测试日志内容来推断成功。每条结果最少有以下字段，缺值用明确的缺失状态，不能填假 hash 或虚构命令。

| 字段组 | 字段 |
|---|---|
| 关联 | evidence_id、task_id、fixture_id、requirement_hash、plan_hash、decision_revision |
| 源码 | commit、tracked_diff_hash、参与构建的未跟踪输入清单及 hash；路径/凭据等非构建私有信息不采集 |
| 构建 | compiler_hash、target、feature、Rust/LLVM/Z3、链接/优化/检测配置、runtime/FFI/final artifact hashes |
| 执行 | command、环境中影响结果的选项、输入/seed、start/end、exit、发现/运行/忽略测试数量 |
| 观察 | expected、actual、result_class、route/profile/MIR digest、verifier 原始状态、性能/内存/并发观测 |
| 存储 | raw_log_path/hash、不可变位置、保留期限、复跑步骤、限制 |
| 累计链 | sequence_id、checkpoint、parent_hash、source_patch、累计回归、数据与缓存变化、人工介入 |

判定类别使用 `已通过 / 明确拒绝 / 环境未验证 / 不支持 / 未解释失败 / 未运行`。明确拒绝只有在固定 oracle 要求拒绝时才是正当通过；必需可执行程序被拒绝仍未完成。exit 0、测试匹配数 0、运行时跳过、只构建未执行、仅有摘要无日志都不能证明能力通过。

**身份失效**：源码/差异、需求、MIR/TypeDesc、模块摘要、目标、编译选项、受信 FFI/证明假设或工具链变化后，依赖它们的旧结果不再是当前证据。可以保存历史趋势，不能将不同提交的专项绿灯拼成同一 RC。ASan/TSan 等配置必然不同，均须来自同一候选源码并分别记录构建身份；性能使用非检测构建，不能将插桩开销混作语言回退。

**产物完整性**：编译器、native object、runtime archive 与外部库必须实际匹配 manifest；环境里一个旧 mimi 可执行文件不能代表当前工作树。B-09 的收集器须校验 hash 与执行结果，结构检查器不承担这个职责。独立检测控制样本用于证明工具有效，发布源码/产物不携带故障控制符号。

**保留**：任务签收前导出不可变证据，设置保留期限，RC 验证下载/复跑入口可用。当前 devdocs 被忽略，本轮增加的本地清单与检查器不是远程归档完成的证据；B-09 仍未验收。存储不足要记录环境失败和所需空间，不删除原始失败记录或并发任务的构建目录来制造通过。

## 5. 清单格式与结构检查

[plan.toml](plan.toml) 使用 schema_version=1：tasks 保存 id、phase、required、status、depends_on、decision_dependencies、goals、evidence、blocked_reason；decisions 保存 id、status、evidence。前置在 02 中定义，机器文件展开 ranges；二者差异使检查失败。目标映射给每个任务至少一个 G1～G7，基础任务可以覆盖全部目标。

运行：

```bash
python3 devdocs/V0.2/tools/check_plan.py
python3 devdocs/V0.2/tools/check_plan.py --ready
```

结构检查覆盖任务/决策重复或遗漏、未知前置、阶段缩写、依赖环、级别/phase/依赖漂移、无目标任务、非法状态、已验收缺证据或前置未完成、文档链接/章节锚和文件格式。A-08 的依赖闭包必须包含全部必需任务，且不能把实验任务意外变成发布前置。`--ready` 仅列台账中前置满足的待办/设计任务，不代替工程负责人对输入、资源与安全边界的判断。

工具**不**执行 Mimi、不验证日志真实性/签名、不判断语义正确性、不把证据路径存在认作 L1/L2/L3 通过，也不自动发布。B-09 的完整验收还需要实际收集器、fixture runner、工件导出与反例验证；当前清单和检查器只是已落地的规划基础。

## 6. 容量、检查节奏与范围纪律

B-08 以“完整能力家族验收、默认路由覆盖、旧生产边退出、应用检查点通过”作为吞吐单位。分别估算语义、实现、测试/检测、审阅和重做成本，记录可用人员/机器/模型预算、最长验证时间、存储需求与余量；没有实际数据不承诺日期。

每个工作包结束更新台账和证据；每次公共 schema/语义改判复查受影响任务；每个阶段出口复采相应应用；RC 对固定源码完整复采。每次检查报告目标分母、验收数、未验证数、最高优先级阻塞与下一项可验收产物。结构检查绿灯、切片数量和受限岛成功不能替代这些指标。

发现 L1/L2/L3、权限边界、义务守恒或成本保证破坏，停止扩大受影响默认支持面，保留反例并解决根因；调查和独立验收建设可以继续。若工作量超出容量，增加阶段与资源或继续开发版本，不把 G1～G7、四应用、公开 stdlib、原 16 项题或两条累计链删出发布分母。
