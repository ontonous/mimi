# 0.2 迁移、风险和发布门禁

> 状态：发布规划，不代表已经发布或已批准 breaking。现行规则仍由 [内核卡](../kernel-card.md)、[语言规范](../../docs/language-spec.md) 与当前源码决定。0.2 任何改判必须先经过 [待裁决问题](05-待裁决问题.md)，并在同一 phase 重新挣回不变量绿色。

## 1. 与 0.1.x 主线的交接

**2026-09-29 用户更新的硬前置**：普通 Map/Any 所有权、两个 Actor fallback 和四类可达 legacy owner 必须在 `0.1.11-dev` 完成收口，全部通过后才切换至 `0.2.0-dev`。详见 [0.1.11 交接门禁](09-0.1.11交接门禁.md)。下文允许提前开展的设计/需求工作不代表允许提前改开发版本或搬移这些未完成责任。

0.1.x 的 [MIR 执行计划](../MIR_EXECUTION_PLAN_2026-09-06.md)继续管理当前切片、四类 legacy owner 和旧实现删除。0.2 语义设计与真实程序需求可先行，但 0.2 发布不能借旧 compatibility 路径承载新增语义并在报告中称其为 Canonical。交接产物是**按能力家族的矩阵**：源码准入、TypeDesc/MIR、validator、reference、bytecode、native、verifier、默认 route、直接 API、旧实现可达性和删除条件。

2026-09-29 的实测差距和对应补强见 [现状与补强](07-2026-09-29现状与补强.md)。交接时要把普通 Map/Any 与已闭合的受限 MapRoot 分列；Actor `runs Flow` 的 VM 成功/native E0722、导出 C ABI body 的具名 compatibility 与显式 MIR 拒绝、`bool` 合同的 E0439 分歧、四个旧 owner 均作为独立行。一次失败的 `--zero` census 可以是诚实证据，但不能提供“全 Canonical”结论；whole-program route、per-function emitter eligibility 和 build failure 分类须分别记录。

0.2 不要求所有历史/实验语言表面均迁入 Canonical 才能发布；它要求**G1～G7 的完整目标面、W1～W4、组合网格及其完整被调用图**不依赖隐藏语义回退。与目标无关的历史/研究形状可明确标为实验或拒绝，必需形状不能靠这个标签免验。旧 owner 在其他隔离能力中仍存在时，报告其确切边界，不能写“全局 legacy 已清零”。

## 2. 预计 breaking 变更与迁移办法

| 变更 | 当前可依赖规则 | 0.2 候选规则 | 迁移与验收 |
|---|---|---|---|
| 普通容器的复制/修改 | 现有类型、move、clone 与具体 backend 行为 | 逻辑值隔离，物理复制可能由实现选择 | 提供旧赋值/传参行为对照；必要时显式 `copy/clone` 或独占缓冲区；快照隔离与成本测试 |
| `MutexGuard` 等清理资源 | 显式 `mutex_unlock`，遗漏 E0256 | 候选：离域自动释放；显式释放仍可提前发生 | 迁移示例必须区分“释放锁”与“完成业务提交”；二次 unlock/借用后使用负测继续有效 |
| 部分 move 与清理顺序 | 当前由具体资源分析、`defer` 与 backend 共同承担 | 候选：只清理仍持有的残余，自动清理顺序确定；可失败终态显式化 | 列出部分构造、早退、失败补偿、嵌套作用域旧新 trace；不把析构错误覆盖原失败 |
| mutate 位置 | 变量/单层字段；嵌套字段、索引传参 E0434；规范延后到 1.x | 候选：统一 root/投影，嵌套与动态元素修改，互斥位置证明 | D-13 修订 §6.2；旧拒绝正例迁为真实写回，同元素/父子冲突仍拒绝；有副作用索引仅求值一次，COW/扩容/错误路径对拍 |
| Map/Any 动态取值 | 默认参数可推导 T，但普通 runtime 缺完整 tag/owner 合同；native 解包正在收紧为拒绝 | 候选：借用/快照/移出区分，缺键与错配区分，擦除保留义务 | D-03 操作表与 V-11；不能靠 raw-bit 转换或默认值掩盖错配，旧严格载荷替换必须归还/结算 |
| Session/导出凭证 | move-only/必须消费 | 保持严格终态结算，取消也是有类型的责任转移 | 旧 `drop` 若曾被允许，按新义务拒绝并给终态建议；`Option`/列表/闭包同样追踪 |
| Flow 使用范围及 Actor 普通字段 | 持续可变业务状态、Actor 业务变化偏向 Flow；不许嵌套 | 候选：阶段合法性用 Flow；普通持久数据用封装/独占修改；独立 Flow 可显式协调 | D-11 必须修订规范 §1.1/§6.4；旧 Flow 不强制改写；新增非 Flow 形状经别名/任务边界验证；直接嵌套仍待 D-04 |
| 并发与线程归属 | task-local 借用、原子与 mailbox 规则分散在 checker/runtime | 候选：可移动/可共享/线程亲和分离，同步可见性与挂起/重入明确 | D-14/F-10 先定合同；借用/guard/不可转移资源逃逸拒绝，消息/锁/join 的 litmus 和 native 检测通过；不新增通用死锁自由承诺 |
| 文件级 `use` merge | 导出合并为裸名；同名冲突报错；无普通限定调用 | 模块身份、别名、限定调用、接口摘要 | 提供自动改写/诊断建议；固定两 `parse` 项目与 stdlib 导入；`::` Flow 调用不破坏 |
| 效果注记 | `with` 已删除，effects 字段不能当强制约束 | 新的有限效果声明 + 私有推断 + 调用传播 | 新拼写待裁决；公开 API 升级需声明上界，隐藏文件/网络效果成为编译错误；历史 `with` 不静默接受 |
| 验证结论 | 普通检查、运行时合约与受限静态证明已有不同入口 | 明确分三层，强制证明模式拒绝未知/超时 | 旧证明缓存失效规则、CLI 退出状态与“可执行但未证明”的迁移表；不把无合约当 `Proven` |
| `SystemToken` | 线性编号，guarded API 以 token 作静态门禁 | 候选：宿主授予具体目录/端点范围能力；一次性凭证独立 | 旧 API 保留/废止需明确版本表；不能把拥有 token 宣传为目录隔离；动态越权测试 |
| 包与模块身份 | 文件级 `use` 加载、公开项合并 | 包/模块/导出稳定身份与可复现锁文件 | 同名不同版本、重导出、离线构建、接口缓存旧摘要的迁移与负测 |
| 成本约束 | 基准与性能调优主要为运行期证据 | `no_alloc` 强制 + 必然/可能/实测报告 | 给出诊断原因链与独占缓冲区改写；可能 COW 分配不能凭一次零分配运行放行 |

上述“候选”需在裁决后更新为确定的旧新程序、编译诊断、自动迁移命令和影响范围。预 1.0 允许破坏性更改，但不允许让真实项目无从定位变化。

## 3. 每项改判的施工顺序

1. **冻结旧行为与新反例**：保存可运行/可拒绝的旧代码、route、VM/native、性能和诊断。旧文档中相互矛盾的结论逐条标注来源与当前有效性。
2. **裁决语义**：写最小语义、正常/失败/取消边界，核对修正案及规范冲突；裁决记录同时包含未选择方案和迁移成本。
3. **先收敛事实源**：checker 与 TypeDesc/MIR 共同承载类型/资源/效果/成本事实；validator 提前拒绝非法 MIR。不得在 runtime 或 LLVM 特判重新猜语义。
4. **完成执行与证明边界**：reference、VM、native 对同一 MIR 差分；verifier 对可证明/不支持分开报告。外部 ABI、stdlib 和 LSP 消费相同接口摘要。
5. **迁移真实程序**：改 W1～W4 中受影响的需求与库；保留旧源和自动迁移记录。未过的自然写法属于产品缺口，不能偷偷改故事。
6. **删除旧权威、同步文档**：目标 profile 的旧生产分支或重复语义判断应物理删除；保留的兼容 owner 有准确调用者和删除前提。更新内核卡、规范、EBNF、stdlib、诊断、CLI help、CHANGELOG。
7. **候选发布复采**：在一个固定提交上运行全套验证和应用任务；成果与限制写入同一证据包。

对于跨度过大的 break，可先在明确的实验 profile 中验证。旧新语义不能同名、同默认路径而静默并存；过渡选择必须可查询并有退出条件。

## 4. 风险台账与停止条件

| 风险 | 早期信号 | 处理/恢复证据 |
|---|---|---|
| COW 让普通写法在热点意外分配 | W3 `no_alloc` 拒绝或 p95 明显漂移 | 明确独占缓冲区/移动规则；成本报告指出分配来源；复采固定热点 |
| 自动清理掩盖持久化/外部失败 | 文件写失败却以 drop 当成功 | 显式 `flush/commit` 有 Result；故障注入证明未丢错；修改 D-02 规则 |
| 泛型/容器义务仍靠特判 | 新 `Option<List<T>>` 又需专用分支 | 保持 0.2 阻塞，修递归规则/IR 与 Drop plan；组合生成器和负测再挣绿，不删除必需形状 |
| MapRoot 成功被外推为普通 Map/Any 已闭合 | 普通 `get/values` 借用后释放、clone/overwrite 漏 payload、production Memcheck 仍有 possible-loss | V-11 建 typed Any 与 owner/borrow/escape/drop receipt，实际普通生产路径跑 L1/L2/L3；MapRoot 和 test-only prototype 单列 |
| 容器析构在 registry 锁内重入或跨锁死锁 | callback/drop 再取 Map/Set/Any 表锁时停住 | V-10/V-11 用重入析构、并发销毁、panic/failure 注入和锁序审计；任何 callback/不受控析构在锁外执行且代际先失效 |
| Flow 组合产生代际别名或隐式事务幻觉 | 子 Flow 转移后父句柄仍可用，失败被错误回滚 | 修复独立句柄/租约和路由，完成 2/4/8 实例；直接嵌套仍依 D-04 裁决，L2/L1/Fault 对拍 |
| Actor/Flow 只有 VM 可跑 | native 把合成转移报 E0722，nested capture/shadow 默认回退 | F-09 建持久状态/mailbox/环境 ABI 与 Checker receipt；native 和 VM 同义，目标图两个旧 fallback 消失 |
| 模块身份随文件顺序/重导出变化 | 私有改动大面积重编或错误绑定 | 稳定 SymbolId + 接口摘要；双 `parse` 和增量 oracle 重跑 |
| 模块影响分析漏掉动态调用或内联依赖 | 工具报告“无影响”而实际构建/行为变化 | 静态图给保守上界，未知 FFI/初始化/生成扩大范围；分开报告 API/合同、实际重编、行为可达调用者与测试 |
| 效果或能力漏过外部 sink | 未声明网络/FFI 调用被推成 pure，路径越界成功 | fail-closed 未知调用；静态和动态门禁分层；保持未支持能力不发布 |
| `no_alloc` 只看主路径 | 回调、析构、错误或取消分支分配 | 全路径传播；构造负例使 checker 拒绝；运行计数作补充证据 |
| Canonical 与旧路径形成双权威 | 默认 CLI 成功但直接 API/`--mir` 语义不同 | route receipt + legacy tripwire；停止扩张、修同一事实源并删除目标旧边 |
| 导出 C ABI body 留在 compatibility 或漏掉合同 | 默认 build 走 `exported-abi-body-compatibility`，显式 MIR 拒绝，或 actor/transition/default 参数中的 FFI 违约未被发现 | M-09/E-06 建 wrapper/body/义务身份；host C、内部递归、direct/CLI/verifier 同源对拍；不把具名兼容当发布通过 |
| 两验证引擎分歧被样例改写掩盖 | 简单 `bool` 后置条件得到 E0439，换 `i32` 才绿 | E-06 以原 bool 正反例修成一致正确结论；复杂公式的不受信边界另行裁决；原始证明状态和诊断留存，不把 Inconclusive 当 Proven |
| 人/AI 评测被参考解或容易任务污染 | 模型没实际运行、维护者是功能原作者，或困难任务被删 | 预注册、隐藏测试、独立交接、保存全部尝试和排除原因；结果不达标则修订 G6 并复测，保持开发版本 |
| 证明缓存复用不同语义对象或受信假设 | 源码、接口、ghost 事实或外部摘要变了仍显示旧 `Proven` | 绑定源码、MIR/TypeDesc、模块摘要、目标数值/证明逻辑、受信假设/FFI 摘要及求解器配置；伪造缓存与未证假设负测 |
| 被忽略的 `devdocs/` 是证据唯一存放处 | 发布后无法从提交或发布工件复现门禁 | B-09 在任务验收前导出清单、日志索引与校验和到可版本化或不可变工件，RC 复核可用性；本地副本仅作工作材料 |
| 文档状态与实际任务脱节 | 待裁决被当作已支持，当前 HEAD 引用了另一提交的绿灯 | B-09 用 plan.toml 维护状态，证据绑定 commit/差异/产物/工具链；设计、实现和规范三层状态分开，历史快照不覆盖当前结果 |
| 独立修改题掩盖累积回归 | 每题从干净参考解开始，但连续修改后权限/缓存/取消损坏 | A-10 两条连续链继承代码和外部数据，每点回跑历史测试；A-04 单列整链模型/人类尝试，重置与人工介入计入失败 |
| native 检测覆盖被 Rust harness 冒充 | Rust 测试插桩，但生成 object/runtime/FFI 未受检 | A-11 按产物列覆盖与 hash，以独立故障控制样本核实工具生效；缺失证据不记通过 |
| 阶段名制造隐含串行或互锁 | F-01 等待整个 P1；“已裁决”又要求后续实现先全绿 | 用具体任务前置和设计接受状态开工，P2/P3 跨阶段任务联合验收；结构检查禁止任务依赖写成阶段缩写 |
| 工具链/环境失败被当语义通过 | sanitizer、LLVM、Z3 或目标平台缺失 | 单列 `环境未验证` 和所需条件；相关发布声称暂停直至复采 |

出现 L1 分歧、L2 误准入、L3 内存错误、权限越界、必需程序被削减需求或效果漏标，即停止扩大 0.2 默认准入。修复后保存反例、根因、负测和全量复采；`ignored`、未重现或环境例外不能自动关闭。

## 发布门禁

**G0 语义门**：D-01～D-14 均达到规范已生效，所有影响 G1～G7 的规则已与内核卡/规范/EBNF 对齐；设计已接受不替代实现或发布验收。四程序、组合网格、两条连续链、目标平台和人/AI 评测的分母与数值预算在第一轮相关实现/正式评测前冻结；必需项不得为发布而删减。

**G1 工程门**：G1～G5 的必需语言形状及 W1～W4、组合网格、B-01 登记的全部公开 stdlib 的 Mimi 执行图在 checker/TypeDesc/MIR/validator/reference/VM/native/verifier 能力/route 闭合，G6 的 CLI/LSP 查询读取同一事实；四程序的默认运行完整图有 route 证据，无隐藏 compatibility 或 Canonical-start 后回退；旧边删减与保留 owner 可审计。普通 Map/Any、Actor `runs Flow` 与 nested capture/shadow、带 Mimi body 的 C export 各有独立正反矩阵，不能由受限 MapRoot、诊断性 E0722 或具名 compatibility 代替。外部 C 代码不假称进入 Mimi MIR，必须经受信摘要/ABI/故障边界验收；模块影响对静态图无漏报，包/锁文件离线重建、FFI/component 身份和接口缓存失效通过。

V-12 的嵌套字段/动态元素修改与独占写回、D-03 的 Map/Any 操作表、F-10 的可见性/挂起/线程归属都属于 G1 必需面。不能将合法自然位置继续拒绝、严格义务擦成可 drop 的 Any，或仅在 VM 中正确同步后标为完整支持。

**G2 可靠性门**：固定正例、负例、trap/失败、取消竞态、跨模块、FFI、生成式和故障注入的 L1/L2/L3 通过；native 实际执行的 ASan/Valgrind 或等效证据零未解释内存问题。普通生产 Map/Any 的借用/克隆/覆盖/清理与析构重入、Actor/Flow mailbox/环境寿命、C export wrapper 与内部递归分别复采。普通检查、运行时契约和强制静态证明分层；Verifier 保留现行 Verified Core §5.7 全部八种原始状态，尤其不把 `NoObligations` 当作 `Proven`，旧证明缓存和未证假设不能复用；`bool` 合同的已知 E0439 分歧及所有 FFI 调用点义务须有关闭证据。全部门禁绑定相同候选提交与工具链。

A-11 必须逐个登记生成 native、standalone runtime、FFI 及测试进程的实际检测方式、构建与产物 hash；需要插桩的对象有相应覆盖，ASan/TSan 独立运行且故障控制样本证实检测有效。平台不适用项需等效检测和明确限制，缺证据的必需路径阻塞发布。结构检查器通过只表示计划一致，不能代替此门。

**G3 应用与成本门**：四程序、全部 16 项独立修改及 SEQ-W2/SEQ-W4 的每个累计检查点完成；热缓存与冷构建结果同义，外部数据迁移有 oracle。W3 在 D-10 固定区域内静态无程序可见分配、native 物理计数为零，VM 管理开销单列；性能、编译资源与长期运行预算在 P0 冻结并按预注册口径评判。包/锁文件/离线安装覆盖 W1 与 W4；文档与 CLI 对支持范围一致。

**G4 可写性与发布事实门**：真实模型和独立人类交接均达到预注册 G6 目标，独立题与整链结果分别报告，包含全部尝试、条件、预算、人工干预和失败；不用 Phase F 手工数据作模型结论。未达目标就修订语言/工具/诊断并复测，不降低分母或口径。plan.toml 的任务/决策状态均能定位不可变证据，CHANGELOG、迁移指南、支持矩阵、安装说明与源码一致；最高优先级阻塞项为零。

任何一门未满足，版本保留 `0.2.0-dev` 或 RC 状态，增加开发轮次和资源后复验。**不允许**把 G1～G7、W1～W4、组合网格、全部 16 项持续修改或冻结平台中的失败项移出，再沿用 `0.2.0` 的目标与名称发布。若产品方向确需改变，应另起明确的新产品裁决与版本目标，保留原失败证据；这不算本规划的 0.2 完成。

## 发布证据包

候选版本可在本地 `devdocs/V0.2/evidence/<候选提交>/` 工作，但不能作为唯一发布证据：仓库忽略整个 devdocs。B-09 在 P0 确定可版本化或不可变工件出口与保留规则；每个任务提升为已验收时就导出清单、日志索引、校验和与复跑说明，RC 再核对可用性，不等到发布前才抢救本地记录。实际外部上传与跟踪策略按仓库授权执行；未导出则任务保留验证中。不得强制推送本地 AGENTS.md。

| 文件/表 | 必需字段 |
|---|---|
| `manifest` | commit、工作树摘要、编译器/最终产物 hash、Cargo 版本、Rust/LLVM/Z3、平台/架构、构建 feature、环境、日期、执行者/CI；配置不同的检测构建分别记录 |
| `decisions` | D-01～D-14 的设计接受/实现验证/规范生效状态与证据、旧新规则、受影响条款和迁移链接 |
| `plan` | plan.toml 版本/hash、任务状态、具体前置、目标/决策映射、结构检查结果；任务结果与计划结构结论分开 |
| `support-matrix` | 每个已发布 profile 的源码准入、MIR、四消费者、verifier 状态、默认/显式/直接 API route、旧 owner；MapRoot/ordinary Map、C import/export、Flow/Actor 分列 |
| `route-census` | 输入种类与完整分母、whole-program Canonical/compatibility/拒绝、per-function emitter eligibility、build_failed 的真实能力/库目标/环境分类、两个旧 Actor fallback 和四 owner 的删除前提 |
| `applications` | W1～W4、16 项独立修改、SEQ-W2/SEQ-W4、组合网格分母；每项结果/失败分类/oracle/hash；链父检查点、累计回归、缓存与数据迁移 |
| `invariants` | L1/L2/L3、生成式、ASan/Valgrind、Flow/取消/FFI/能力负测与未运行原因；证明结果原始状态、受信假设和验证器配置 |
| `cost-performance` | 静态 no_alloc、必然/可能/实测、固定机器/输入、重复运行、噪声与预算结果 |
| `native-detection` | 最终 binary/object/runtime/FFI hash、插桩或动态检测覆盖、原始日志、故障控制样本结果、未覆盖段/替代证据与适用平台 |
| `human-ai-eval` | 独立维护者和模型版本、提示/预算、四条件尝试、逐任务与整链输出、干预/重置、成功率/修复轮/回归、限制 |
| `release-notes` | 已支持、实验、拒绝、breaking 与迁移、已知缺口、安装步骤 |
| `artifact-index` | 每份证据的内容 hash、来源提交/CI job、不可变访问位置、保留期限和复跑命令 |

证据可以由 CI 生成，但报告正文必须明确**结论适用的 profile 和日期**。没有日志的“全绿”、仅 module verify、仅 `--mir` 单例和历史成功数字都不满足发布证据。
