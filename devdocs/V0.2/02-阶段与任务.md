# 0.2 阶段路线与可执行任务

> 状态：规划队列，建立于 2026-09-24，2026-09-29 深化。任务状态统一记在 [plan.toml](plan.toml)；除 B-09 的规划工具处于**设计中**外，任务均未开始，没有已验收能力。现行 0.1.x 施工仍由 [MIR 执行计划](../MIR_EXECUTION_PLAN_2026-09-06.md)维护。本表的 `0.2` 是外部里程碑，不给现有内部 sprint 强行改编号。

## 1. 任务判定规则

**级别**：`必需` 是 0.2 发布门禁，不能因估算过大、技术困难或单个样例已过而降级；`实验` 只适用于 [总览的非目标](README.md#明确不纳入-02-发布承诺) 或正式必需能力施工前的探针，不能替代必需任务。任务完成需保存提交、固定用例、结果与路由/信任边界。代码类任务遵循一条完整能力家族的 checker → MIR validator → reference/bytecode/native → verifier 能力判定 → 默认入口 → 旧路径删减；短暂不完整切片只可标为实验，正式发布前必须闭合全部必需家族。

**分工角色**是责任面，不指定人员：`语义` 管理规则/规范；`前端` 管理 parser/checker/模块解析；`中枢` 管理 TypeDesc/MIR/validator/route；`执行` 管理 reference/VM/native/runtime；`验证` 管理 SMT 能力和证据；`工具` 管理 CLI/LSP/查询；`产品` 管理真实程序、安装和实验。一个任务可以跨角色，但只有一个验收结论。

**开工与验收分开**：表中的“依赖”是正式验收前置；调查、oracle、语义探针和明确隔离的原型可提前开始，但不能绕过前置提升为已验收。设计决定达到“设计已接受”后可指导实验施工；只有实现、不变量与规范同步均完成才成为“规范已生效”。阶段是报告分组，不是隐含的全阶段依赖边。具体排队、证据字段和跨阶段交付见 [执行与证据合同](08-执行与证据合同.md)。

**全阶段不变量**：

- L1：对同一已准入程序/同一 MIR，reference、VM、native 的值、输出、退出、trap/错误分类一致；旧双后端用例继续有效。
- L2：非法源码或 MIR 在任何执行/LLVM/Z3/外部效果前拒绝；未支持形状和证明能力明确标注。
- L3：TypeDesc 与 MIR 决定 Move/Clone/Drop/Borrow；实际 sanitizer/Valgrind/ASan 证明已发布形状无内存错误。工具缺失标记为未验证，不写成通过。
- 默认路由和直接 API 都受相同准入；Canonical 启动后不能转 compatibility；发布家族的旧生产语义边必须可审计地下降。
