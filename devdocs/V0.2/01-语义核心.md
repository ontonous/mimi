# 0.2 候选语义核心：先裁决四件事

> 状态：**设计提案**。这里的“应当”表示 0.2 候选合同，不表示当前编译器已支持。当前写法以 [内核卡](../kernel-card.md)和[语言规范](../../docs/language-spec.md)为准。发生冲突时先完成 [裁决](05-待裁决问题.md)、规范改写、迁移、测试，再提升本文件的条目为实施合同。

## 0. 定位与规则数量

0.2 首先裁决四个可组合的基础问题：

1. 普通值复制后如何修改、如何计成本；
2. 独占资源离开作用域时如何清理；
3. 协议义务如何在正常、失败与取消路径上结算；
4. 模块公开接口如何限制名称、权限、效果与修改影响。

Flow、效果、能力、成本和 AI 工具由这四项生长。验证方式不是为每种新语法补特判，而是让同一规则穿过记录、`Option`/`Result`、列表、普通 Map/Any、泛型、闭包、Flow payload 和任务边界。受限 MapRoot 是施工证据，不代表普通容器已经获得相同语义。

### 0.1 五类事实不能互相替代

| 事实 | 回答的问题 | 例子 |
|---|---|---|
| 值语义 | 复制后，一个值的修改会不会影响另一个？ | 普通配置、字符串、列表快照 |
| 所有权/访问权 | 当前由谁持有、谁能独占修改、何时可借用？ | 文件、缓冲区、记录字段 |
| 协议义务 | 还必须完成哪个终态操作？ | 会话 close、导出任务成功/失败/取消结算 |
| 效果与能力 | 调用可能做什么；是否获准操作指定资源？ | 文件读取、网络发送、阻塞 |
| 成本 | 哪些资源代价必然/可能发生？ | 分配、复制、释放、设备搬运 |

这些是**可组合的属性**，不把类型固定分成互斥的“值/资源/身份”三个箱子。节点 ID 可以被复制，但其目标的存活仍由所属存储管理；记录含独占资源就不能复制；列表含严格义务就不能被普通析构抹掉义务。

## 1. 普通值：可观察的隔离，明确的成本

**候选合同 V-1**：一次普通值的*逻辑复制*产生独立的可观察值。之后独占修改其中一个，不改变另一个。编译器可用内联复制、move 消除、引用计数、写时复制或持久化结构实现；这些实现不能改变值的可观察行为。需要共享身份时，程序必须使用显式身份/共享类型。

**候选合同 V-2**：实际复制动作和可复制资格分开。类型的组成决定能否逻辑复制；语法是否默认复制大对象、何时要求显式 `copy/clone`，由 [D-01](05-待裁决问题.md#d-01-普通值的复制操作) 的成本与可用性实验决定。0.2 不能为了宣传“值语义”而悄悄给热点加入不可见的分配。

**候选合同 V-3**：普通值的析构只释放实现拥有的存储，不代表业务协议完成。`mutate` 保持独占访问，不允许仍可见的两个普通值因底层共享存储而互相改动。跨任务分享可变对象必须显式表达身份与同步边界。

| 验收例 | 应观察到 | 应拒绝或报告 |
|---|---|---|
| 复制列表快照后编辑原列表 | 快照内容不变 | 若发生首次写时复制，在成本报告中列为“可能分配/复制” |
| 记录含独占文件 | 可移动，不可逻辑复制 | 复制尝试在 checker 拒绝 |
| `NodeId` 复制后更新同一节点 | 两个 ID 指向同一存储身份 | 若节点已删除/世代失效，访问给出明确错误 |
| `no_alloc` 路径修改共享普通列表 | 结果正确或静态拒绝 | 不允许运行时才发现隐藏分配 |

**实现问题**：先形成 type-level 属性推导与布局/Drop plan，再让 MIR 明示 Move/Clone/Drop/Borrow。不能用 LLVM 指针形状、类型名字符串或某个 builtin 的特殊分支推断是否复制。

普通 Map/Any 还有一条必要的身份规则：擦除静态载荷类型不能擦除运行期描述、owner 与借用/快照寿命。`set/get/values/remove/clone/destroy`、覆盖旧值、从 Map 逃逸及失败后的清理必须服从同一值隔离与资源义务；析构可重入时须先使旧句柄代际失效，再在 registry 锁外运行不受控清理。这是 [V-11](02-阶段与任务.md#4-p1值所有权与清理) 的候选合同，不是现行 ordinary Map/Any 已实现的声明。

### 1.1 修改位置与独占访问

**候选合同 V-4**：修改位置由稳定 root 身份与字段/索引投影构成。嵌套字段、单个动态索引的 mutate 传参必须能实际写回；索引与实参按既定求值序计算一次。位置不是临时值副本，读取、借用、移动和残余义务引用同一位置。当前 E0434 仅准变量/单层字段的限制需经 [D-13](05-待裁决问题.md#d-13-修改位置别名与求值顺序) 改判。

独占判定比较投影关系：不相交字段可并存；父子位置、同元素和可能重叠且无证明的动态访问不得并存。动态拆分可以返回可检查的不相交凭证，失败不产生两个独占借用。COW 唯一化先于借用暴露，活跃借用阻止令其失效的扩容/替换。普通失败不自动回滚此前写入；Flow 的失败归还遵循专门合同。V-12 必须同时验证求值序、错误路径、清理、快照隔离和 no_alloc 成本。

### 1.2 Map/Any 取值与所有权

下表是 D-03 必须裁决的候选操作合同；操作名用于说明职责，**不是已生效 API 或最终语法**。静态同类型 Map 与动态异构 Map 共享所有权模型；动态版本另检查 payload TypeDesc。擦除类型须保留 Copy、自动清理、严格义务与跨任务属性，不能让任意 Any 默认获得这些权限。

| 操作职责 | 所有权与失败后置条件 | 必需反例 |
|---|---|---|
| pack / checked unpack | 保留 payload 描述和 owner；错配不产生伪 T，也不销毁原值 | 存 string 按 i32 解包；伪造或过期 descriptor |
| borrow get | 借用期内 owner 存活，阻止冲突修改/销毁；缺键与错配分别返回 | get 后销毁/覆盖原 entry，再用借用 |
| snapshot get / values | 仅对满足逻辑复制属性的载荷创建独立可观察值；实现成本可见 | 快照后修改原 Map 导致快照变化；复制严格凭证 |
| take / remove | 移出载荷义务给调用者，剩余 Map 保留其余义务；失败不丢 owner | 删除 Session 后忽略返回值；重复认领同一 entry |
| set / replace | 插入新载荷转移其 owner；旧严格义务必须返回或显式结算，不能隐式遗弃 | 覆盖未结算 ExportTicket；插入失败双持有或丢失 |
| clone | 由递归复制资格决定；共享实现仍需值隔离，不能复制独占/严格义务 | Any 包装后绕过不可复制限制 |
| destroy | 只清理仍持有且允许自动清理的残余；严格义务未结算则拒绝 | 动态包装让 Session 通过普通 drop 消失 |

`get_or_default` 的 default 只能处理缺键，不能证明既有 entry 的类型；类型不符必须产生规定的类型化失败，不能截断 raw bits、返回冒充 T 的值或静默改用 default。首版如何表达借用 get、快照 get 与移出由 D-03 确定。严格义务经动态包装仍须能安全传递、取回和结算；不能以全禁该组合替代 G2。

## 2. 独占资源与协议义务：两种退出规则

现行 `linear T` 是 move-only 且必须恰一次消费；`linear drop T` 可显式 drop；`MutexGuard` 当前须显式 `mutex_unlock`，遗漏报 E0256。0.2 候选把“需要清理”与“必须结算协议”拆开：

| 类型属性 | 可以复制？ | 正常作用域退出 | `Err`/`?`/Flow rollback/协作取消 |
|---|---|---|---|
| 普通值 | 由字段属性决定 | 自动释放其拥有的存储 | 同规则，按实际已执行的退出路径 |
| 自动清理的独占资源 | 否；可 move/借用 | 调用规定的、不可抛出的清理动作 | 清理被执行；若需要可报告的 close/flush 错误，必须另有显式操作 |
| 严格协议义务 | 否；只能 move、返回或合法终态结算 | 未结算即编译错误 | 每条路径均需显式处理、转交或有类型的取消结算 |
| 身份句柄 | 复制标识是否允许由句柄契约决定 | 释放标识不自动销毁目标 | 目标存活由 owner/世代/租约检查 |

**候选合同 R-1**：自动清理只保证本进程实际执行到的离域路径调用清理逻辑。进程被强制终止、`abort`、断电、外部设备失联时不保证清理发生。不可抛出的自动清理不得冒充已成功刷盘、提交事务或已获远端确认；这些要求必须是可观察、可失败的显式操作。

**候选合同 R-2**：严格协议义务的合法终态由类型/状态机列出。`drop` 一般不能替代 `commit`、`close_session`、`cancel_and_join` 等终态。取消分为**发出请求**、**等待/移交清理责任**和**确认本地义务结算**；编译器只能保证责任不丢，不能保证远端响应或任务终止。

**候选合同 R-3**：复合类型递归继承义务。容器整体 move 转移元素义务；按元素取出后剩余容器继续拥有残余义务；分支汇合必须给出同一责任归属；闭包捕获与泛型实例遵守同样规则。`Option<Session>`、`List<File>`、`Result<ExportTicket,E>`、`Record<MutexGuard>` 不再分别需要一套用户可见的例外规则。

**候选合同 R-4**：Flow 转移仍精确负责 source/target 状态身份与失败归还。自动清理不得悄悄吞掉 `fails E`、`Fault`、`Trap` 的分类，也不得在回滚前做不可逆外部效果。已有数值确定性和双后端等价保持。

**候选合同 R-5**：离域清理只作用于仍由本作用域持有、已经初始化的部分；部分 move 后只清理残余字段，不能重复释放已转移字段。建议以作用域内构造的逆序作为确定性默认顺序，并明确定义它与 `defer`/失败补偿的先后。清理动作不得以另一个错误覆盖原有 `Err`/`Fault`；需要向调用者报告的 `flush`、提交或关闭失败应是显式、可失败的操作。上述顺序和错误处理在 [D-02](05-待裁决问题.md#d-02-自动清理与严格义务边界) 中正式裁决。

**候选合同 R-6**：每个严格义务有且只有一个当前责任人；在进程继续执行且终态处理完成的前提下，成功、失败、取消竞态最多产生一个、且必须结算为一个本地终态回执。取消请求不消费责任，直到确认终止或显式移交；若永远没有确认，责任保持可追踪的未决状态，不能凭超时伪造结算。进程 abort、断电或永不响应不承诺终态最终到达。跨任务、FFI 和宿主边界必须有明确谁持有最终结算责任的合同。

关于 `MutexGuard` 是否从“显式 unlock 义务”改成“离域自动释放”、如何表示可失败的文件 close，需先通过 [D-02](05-待裁决问题.md#d-02-自动清理与严格义务边界)。这会改变内核卡 §3 的强制诊断，必须有旧新代码与负例迁移表。

## 3. Flow：只承担阶段合法性，支持显式组合

**候选合同 F-1**：操作是否允许取决于阶段时使用 Flow。仅需控制谁能修改普通数据时，使用封装、独占所有权、`view/mutate` 和数据不变量。文档关闭后的提交、导出进行中资源保留、取消后终态结算适合 Flow；光标位置、缓存条目、节点坐标通常不需要独立 Flow。普通数据可以跨调用持久存在，但这需要明确修订现行规范 §1.1“持续可变业务状态须进入 Flow”及 §6.4“Actor 业务状态变化只由 Flow 承载”的范围；见 [D-11](05-待裁决问题.md#d-11-长期普通状态与-actor)。

阶段性质由 API/类型作者显式声明；编译器不能从任意布尔字段推断“这是业务阶段”。0.2 能静态检查**声明了 Flow/协议的边界**，并用 lint/审阅指导未声明的设计选择，不声称自动发现全部隐藏业务协议。

**候选合同 F-2**：Flow 可以持有普通数据、独占资源和协议义务，转移时依照同一 ownership plan 迁移或结算。Flow 并不能取代编译器对别名、逃逸、跨任务独占权的检查。对外叙事改为“让重要生命周期约束贴近业务状态”，避免声称 Flow 本身消灭所有借用检查。

**候选合同 F-3**：0.2 必须能在真实程序中**显式协调多个独立 Flow 实例**，以 2/4/8 实例、交错失败/取消和动态失效句柄作为验收网格；每个实例有明确 owner、路由顺序和失败归属，不引入隐式状态乘积、隐式事务或自动跨 Flow 回滚。直接把 Flow 实例嵌入另一个 Flow payload 会触及现行修正案的永久禁令，须以 [D-04](05-待裁决问题.md#d-04-flow-组合与嵌套) 单独裁决。推荐**owner 持有不透明子 Flow 句柄/受控租约**：句柄保留 Flow 身份与世代，租约在转移、取消或 owner 离域时失效；静态已知状态使用 typestate，动态边界返回类型化状态错误。一个子 Flow 失败不自动回滚另一个已完成的外部效果。

**候选合同 F-4**：多 Flow 的可用组合属于 0.2 必需合同。若另提供名为 Grouped Flow 的路由器层，它必须在上述规则之上定义固定全序事件路由、资源不相交和明确失败边界；是否采用该抽象不影响 F-3 的必需性。不能以数学上未经证明的复杂度结论或外部合规宣传代替真实验收。

Actor 声明 `runs Flow` 时，mailbox 中的状态身份、字段 effect 和合成转移仍受 F-1～F-4 约束；自调用、闭包捕获与消息间的状态延续必须在 VM/native/验证器有同一事实源。当前 native E0722 是尚未建模的准确拒绝，不能据此把这项能力记为完成。

### 3.1 并发可见性与挂起

**候选合同 F-5**：值的可转移、可共享和线程亲和分别推导，owned 不自动表示可跨任务。view/mutate 借用、持有的 guard 和线程绑定资源不得通过闭包/Any/mailbox 擦除限制。跨挂起点保留资源的合法性必须显式检查。

**候选合同 F-6**：同步操作建立可查询的可见性边：任务内程序序、发送到对应接收、unlock 到后续成功 lock、完成到 join 确认。mailbox 每发送者顺序、跨发送者允许交错、原子顺序与 turn 重入点经 [D-14](05-待裁决问题.md#d-14-并发可见性挂起与线程归属) 裁决。L1 比较允许的观察轨迹，不能要求不同真实线程运行恰好同一打印顺序，也不能因此允许丢消息/重复终态。

线程绑定资源的清理在其允许线程执行，转移必须保留该责任。运行时允许的同步与数据访问通过 F-10/F-06/F-09 验证；任意锁图无死锁、公平调度和远端必停不属于承诺。native 检测覆盖按 A-11 单列，Rust 测试进程受到检查不能替代生成程序受到检查。

## 4. 模块接口：名称与修改影响都要有边界

现行 `use` 把公开项裸名合并，同名导出报错，普通 `M::f` 调用不支持。0.2 候选改变这一裁决：

**候选合同 M-1**：模块有独立身份和公开接口。至少支持显式导入、别名与限定访问；两个库都导出 `parse` 时可并存。裸名导入是否保留为显式选择由 [D-05](05-待裁决问题.md#d-05-模块名称与语法) 决定。限定符具体拼写晚于符号解析规则裁决，不能照搬 Flow 的 `::` 而制造歧义。

**候选合同 M-2**：公开接口记录导出符号的类型、泛型/权限、资源转移、效果上界、关键成本约束和必要的合约摘要。模块内部实现细节、局部调用节点 ID 与文件遍历顺序不能改变其公开符号身份。接口摘要变化可由工具比较并列出受影响的调用方。

**候选合同 M-3**：跨模块解析、泛型实例化、trait/impl、标准库导入、LSP 跳转和 component/FFI 使用同一身份。影响分析必须对**支持的静态依赖图保守完整**：允许说明过度包含的原因，不允许漏报实际可能受影响调用方。工具分别报告①公开 API/合同兼容性，②实际需要重编的单元，③私有行为变化可能触达的调用者与测试；公开摘要不变只说明第一项未变，绝不说明行为或测试无影响。内联、常量折叠或单态化造成的实际重编另列。反射、动态加载、模块初始化/编译期生成和未知 FFI 依赖必须扩大影响范围或标成未知，不能承诺精确影响集。

**候选合同 M-4**：导入图和缓存身份可复现。循环依赖、同名别名、重导出与版本冲突给出确定性诊断；实现仅证明其支持的模块形状，未知复杂图 fail-closed。

**候选合同 M-5**：包锁文件、依赖来源、目标平台和公开接口摘要共同参与构建身份。模块名与包版本的身份、初始化顺序、重导出权限和循环图处理要先定语义，再谈增量缓存。缓存命中不得让旧效果/能力/成本摘要继续服务新源码。

带 Mimi 实现体的 C 导出同时有外部 C wrapper 与内部 Mimi body 两种 ABI 身份；内部调用、递归和验证义务必须指向 body，host C 只通过 wrapper 和受信摘要进入。编译器须把二者绑定到同一模块接口而不混用调用约定。现行默认 `exported-abi-body-compatibility` 与显式 MIR 拒绝说明 [M-09](02-阶段与任务.md#5-p2模块接口和增量边界) 仍待实现。

## 5. 效果与能力：分别表达“可能做什么”和“获准做什么”

现行 `with` 效果注记已经因缺乏强制语义而删除。0.2 只有在**调用链实际强制检查**时才重新引入有限效果体系；旧拼写不自动复活。

**候选合同 E-1**：首轮有限效果集合覆盖文件读/写、网络、共享可变访问、阻塞、挂起（以及启动异步任务所需的明确分类）。纯函数效果集为空。私有实现推断效果；公开接口声明允许上界；调用者必须容纳被调用者的效果；高阶函数、闭包与泛型回调传播效果参数或上界。

**候选合同 E-2**：未知 builtin、FFI、动态调用、反射或兼容实现不能被默认为纯。要么保守赋予明确上界，要么在限制性调用点拒绝。verifier 对效果不支持时给出现行原始结果 `NotInTrustedSubset`；已建模却无法判定时另给 `SolverUnknown`/`Timeout`，不输出伪 `Proven`。Flow rollback turn 中的不可逆效果继续受失败代数约束。

**候选合同 E-3**：`mimi check` 的类型/资源/效果通过、运行时契约检查通过、SMT 静态 `Proven` 是三个不同结论。普通编译可接受不属于证明子集的程序，但只有运行时 evaluator 实际支持的合约才能声称“运行时已检查”；不支持的合约应明确拒绝该模式或标为未验证。强制静态证明沿用现行 [Verified Core §5.7](../../docs/language-spec.md#57-result-states-stable) 的完整结果集：`NotInTrustedSubset`、`SolverUnknown`、`Timeout`、`InfrastructureError`、`RuntimeOnlyContract` 等均不能伪装为 `Proven`；`NoObligations` 是无待证义务，不代表某个性质已获证明。证明产物绑定源码、接口摘要、MIR/TypeDesc 身份、目标机数值语义、受信逻辑/假设和验证器版本，不能复用不同程序的旧证明；见 [D-12](05-待裁决问题.md#d-12-可执行与可证明的边界)。

**候选合同 C-1**：能力是对具体资源范围的授权，由入口环境/宿主授予，用户程序不能凭普通构造函数伪造。可多次读取的目录权限可以在受控范围内借用；一次性凭证可保持严格线性。授权范围和使用次数来自权限含义，而不是一律套 `SystemToken` 的恰一次消费。

**候选合同 C-2**：静态检查确认调用携带所需能力，运行时边界检查动态路径/端点仍在授权范围。路径/符号链接、任务转移、FFI 代理、权限撤销的细节必须有安全依据；W1 的目录能力和 W4 的端点能力是必需交付，无法安全实现时阻塞 0.2 发布并修复语义或运行时，不能删除这两个故事。当前 `make_token()` 的唯一编号只证明 token 所有权，不构成目录/网络范围隔离的证据。

**候选合同 C-3**：所有**安全 Mimi 代码可达**的同资源入口都纳入授权清单。若 `read_file_guarded` 受限，而普通 `read_file`、stdlib 包装或允许的 FFI 仍可在同一受限上下文绕过，不能宣称目录能力已强制生效。任意不受信的进程内 native FFI 可以直接调用操作系统，不能仅靠 Mimi 类型系统约束；此类调用必须列为受信宿主代码、被禁止，或放进真正的隔离边界。路径授权优先绑定宿主持有的目录/文件对象而非只比较字符串；P0 冻结的每个目标平台都须提供 W1/W4 所需防竞态保证，缺失时该平台验收和 0.2 发布保持阻塞，不能在 RC 临时删平台或缩权限。

效果是行为上界，能力是授权依据；`requires/ensures` 是输入输出关系。不能用任意一项悄悄代替另一项。有限集合、外部调用和回调规则见 [D-06](05-待裁决问题.md#d-06-效果集合与公开边界) 与 [D-07](05-待裁决问题.md#d-07-能力的授予与范围)。

## 6. 成本：先让关键保证可兑现

**候选合同 K-1**：0.2 的静态成本约束先覆盖**堆分配与释放、深复制/写时复制、容器扩容、析构和设备搬运的可见分类**；第一个强制保证是“所有可达路径无堆分配”。动态分派、回调、泛型实例、异常退出与自动清理进入同一检查。无法证明时拒绝约束并展示原因链。

**候选合同 K-2**：成本报告分三列：`必然`（语义和已选择实现均要求）、`可能`（受运行时分支/容量/共享程度影响）、`本次实测`（指定输入和构建配置）。单次测量不构成最坏路径保证。优化更换实现后可改变“可能”与实测，但不得破坏已声明的强制边界。

**候选合同 K-3**：0.2 不承诺泛化的 CPU 时间上界。对数组/音频热点提供固定输入、配置、目标机器下的运行时间、峰值内存、分配次数与回归阈值。设备/GPU 在 0.2 仅保留类型与外部调用边界的设计位置，实际搬运能力须另作 profile。

**候选合同 K-4**：`no_alloc` 的静态对象是被标记调用区域的**程序可见堆分配事件**，包括其调用、COW、扩容和已执行的自动清理；若要求 native 物理分配也为零，运行时、stdlib 与 FFI 必须提供可审计摘要。VM 自身的解释器框架分配、首次加载/链接和测试采样器开销另列，不可混入语言保证或用它推翻同一 MIR 的语义。区域入口、预分配、错误与取消路径、跨线程分配及 warm-up 边界在 [D-10](05-待裁决问题.md#d-10-成本约束范围) 定案。

## 7. 编译器事实查询：给人和 AI 同一证据

语义查询的最小问题集：一个符号的定义/调用/引用；Flow 当前合法边；某个值的 owner 与未结算义务；函数效果及其来源；成本“必然/可能”的原因链；模块接口改动影响；证明结果与不支持原因。输出应带稳定 ID、源码跨度、编译器/接口版本、route 与信任等级，可供 CLI、LSP 和外部工具复用。至少区分`静态已检查`、`带前提的上界`、`仅本次实测`、`未支持`、`缓存已失效`；不能把缓存过期或部分调用图当成确定事实。

有类型空位与语义编辑事务安排在查询接口之后。空位必须显式标为**未完成**，记录期望类型、持有资源、允许效果和待证明义务；含空位代码不可被误报为可发布。AI 的修改仍由独立 checker、测试与构建验证，工具响应不是证明本身。

## 8. 从候选到规范的提升条件

每个语义条目都必须通过以下闭环才可标为“0.2 已生效”：

1. 最小操作语义/类型规则、正例与反例写清，包含正常、失败、取消或终止的适用边界；
2. 对现行内核卡、语言规范和架构修正案逐条列出保留/修改/废止，以及迁移示例；
3. checker、Canonical MIR/TypeDesc/validator、reference、bytecode、native、verifier 能力判定使用同一事实；
4. 默认 `run/build/verify` 与直接 API 不存在绕行旧语义的隐藏路径；L1/L2/L3、负测、实际 sanitizer 和成本测试重新挣绿；
5. 该规则覆盖四个验收程序中所有实际使用点，并至少在一个程序的真实修改中自然使用；独立组合网格覆盖未由应用恰好触达的必需形状，不把需求改写为编译器刚好支持的形状。

细分任务见 [阶段与任务](02-阶段与任务.md)，可复现证据格式见 [验收程序与评测](03-验收程序与评测.md)。
